# 兼容性维护约定

## 按发布记录确定兼容范围

- 以最近一次公开发布对应的 Git 标签或提交为核对基线。清理时沿提交历史确认接口、配置键、持久化格式、导入导出包和更新清单是否已有公开依赖，不能仅凭名称或版本号判断。
- 已随公开版本交付的接口、数据格式和兼容分支继续保留，确保已发布版本能按现有约定升级、读取数据和导入数据包。预发布版本只要已公开交付，也属于已发布版本。需要改变已发布契约时，应另行评估迁移和影响，不随日常开发清理一并删除。
- 下一版本开发期间若多次调整同一实现，可以删除只为未公开发布的中间接口或格式服务的别名、转换和兼容分支。删除前确认当前实现及任何已发布版本都不依赖它；无法确认时先保留。
- 当前仍在使用的版本化接口和存储键、格式校验、损坏数据处理以及平台适配不是旧版兼容，不因带有版本号或回退逻辑而删除。

## 设备更新不参与应用兼容清理

已正式发布的 ESP-IDF 固件及应用侧设备更新适配不属于应用版本兼容清理范围。固件更新协议、清单及其发布地址、硬件匹配、升级传输和相关兼容逻辑须保持不变，不随应用接口或数据格式清理改动。

## 旧接口标记

旧接口及相关兼容代码必须通过以下任一方式明确标记，便于后续检索：

- 命名包含 `legacy`：Dart 类使用 `Legacy…`，方法和变量使用 `legacy…` / `_legacy…`，独立文件使用 `legacy_…`。
- 在相关入口旁添加 `LEGACY:` 注释，说明对应的旧接口或旧格式。

不适合使用 `legacy` 命名时不强求改名，使用 `LEGACY:` 注释即可。

注释示例：

```dart
// LEGACY: 兼容旧字段 previous_name。
```

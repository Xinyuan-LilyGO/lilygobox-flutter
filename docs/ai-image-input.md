# 模型图片输入能力声明

图片能力仅从“获取模型”接口返回的元数据自动读取，按“模型服务 + 模型 ID”保存，不提供手动设置入口。保存服务后持久化，取消弹窗不保存。旧版可能含手动设置的 `imageInputs` 不参与判断；自动读取结果使用 `discoveredImageInputs` 保存，重新获取模型即可更新。

读取模型列表时，仅解析服务明确返回的 `input_modalities`、`inputModalities`、`input` 或 `architecture.input_modalities` 字符串列表。包含 `image` 表示支持图片；包含 `text` 且没有 `image` 表示仅文本；缺失、空值、格式错误或其他模态保持未声明。每次成功获取模型列表时，以本次返回的能力元数据替换旧结果，缺失声明恢复为未知。这里是能力声明，不是通用检测接口，不发送额外测试请求，不根据模型名称、官方／第三方身份或 HTTP 524 猜测能力。

未声明允许发送图片，实际能否处理仍由模型服务决定。仅文本模型在发送前通过共用 `showAppNotice` 底部通知提示，保留输入内容和附件，不追加聊天消息、不发起请求。历史对话已经包含图片时也阻止继续向仅文本模型回放历史；可切换支持图片的模型，或清空会话后发送纯文本。不能静默丢弃图片后继续发送。

能力声明不会改变图片附件、剪贴板和两种 API 协议的请求格式。删除模型时删除对应声明；修改服务地址、API 协议或供应商预设时清除旧声明，避免将原端点能力误用于新端点。API 密钥不写入能力声明。

# AI 命令执行规则与危险操作确认

本功能在软件执行层实现，不向模型的系统提示词追加安全规则，不修改已有系统提示词或工具描述。只影响 AI 的 run_command 入口，其他工具沿用原有权限检查。

## 执行顺序

1. 固化可执行文件、参数、实际工作目录和操作目的，忽略模型传入的批准标记或规则。
2. 从应用配置目录加载命令规则，匹配当前调用，并检查内置危险操作。
3. 命中 forbidden 时直接返回失败，不展示可批准的按钮，也不启动进程。
4. 默认情况下，命中 prompt 或内置风险时使用现有输入区批准面板请求一次确认；只有在自定义权限中开启“允许运行本机命令”并确认开启“命令免审批”后，才跳过这类确认。
5. 保留原有能力授权。本机命令统一使用“允许运行本机命令”批准，将风险原因合并到同一张批准卡片；不再重复申请文件、网络、设备、固件和安装类别。
6. 用户拒绝、停止或取消时不执行。批准不修改自定义权限开关，也不自动新增 allow 规则。
7. 真正启动进程前再次读取规则。新规则禁止时立即拒绝；规则文件内容发生变化时，本次调用失效，需要重新提交并审核。规则读取失败同样不执行。

文件完全访问和其他能力授权不能跳过命令风险确认。“命令免审批”只跳过 prompt 和内置风险的确认要求，不跳过 forbidden、配置错误、规则变更和取消检查。运行中的进程沿用原有授权，修改规则不会追溯停止已经启动的进程。

## 规则文件

Windows 默认位置：

    %LOCALAPPDATA%\LILYGO\lilygobox\command-rules.json

LOCALAPPDATA 缺失时使用 USERPROFILE 下的 AppData/Local；macOS 使用 ~/Library/Application Support/lilygobox/command-rules.json；Linux 使用 $XDG_CONFIG_HOME/lilygobox/command-rules.json，未设置时使用 ~/.config/lilygobox/command-rules.json。

规则文件由用户手动创建和编辑，无需重启，每次命令执行会重新读取。不加载项目目录中的规则，不接受模型参数指定规则路径。文件不存在表示没有自定义规则，内置危险检测仍然有效。软件不自动写入规则文件，也不新增规则编辑页面。

文件采用 UTF-8 JSON，允许 UTF-8 BOM，最大 64 KiB，最多 256 条规则，每个 prefix 为 1～64 个非空字符串，每个字符串最长 1024 字符；配置缺少必要字段、包含未知字段、编码或 JSON 错误、文件不可读、规则文件为链接或目录时，命令停止执行并显示错误，不静默当成空规则。

示例（按需要选择，不是默认永久黑名单）：

~~~json
{
  "version": 1,
  "rules": [
    { "prefix": ["git", "status"], "decision": "allow" },
    { "prefix": ["git", "reset", "--hard"], "decision": "prompt" },
    { "prefix": ["diskpart"], "decision": "forbidden" },
    { "prefix": ["format.com"], "decision": "forbidden" }
  ]
}
~~~

- allow：规则本身不增加确认要求，不授予原本缺失的能力权限，也不覆盖内置危险检测。
- prompt：默认要求批准；用户明确开启“命令免审批”时跳过确认。
- forbidden：直接拒绝匹配的调用，不能通过“允许一次”放行；需要用户修改规则后重新提交。
- 多条规则命中时取最严格结果：forbidden > prompt > allow。父级 allow 不能覆盖更具体的 forbidden，具体 allow 也不能覆盖父级 forbidden。

prefix 匹配分词后的参数前缀，不使用子串搜索、正则或通配符。首项为程序名时可匹配相同名称的绝对路径；首项为完整路径时只匹配该路径。Windows 程序名和路径忽略大小写、统一斜杠方向；程序名称比较允许省略 .exe/.com。其余参数保持大小写和字面量精确比较，例如 git reset HEAD --hard 不匹配 ["git", "reset", "--hard"]，但仍会被内置危险检测要求批准。需要禁止所有 reset 调用时使用 ["git", "reset"]。

## 内置检测范围

- 强制或递归删除，例如 rm -f/-rf、Remove-Item -Force/-Recurse、CMD rd/rmdir 的 /s 或 /q，以及 del 的强制/静默参数。
- 丢弃本地修改，例如 git reset --hard、git checkout -- 或强制 checkout、git clean 的强制选项、git restore。识别常见 Git 全局参数（例如 -C、-c、--git-dir）后的操作。
- 磁盘和分区操作，例如 format、Format-Volume、Clear-Disk、diskpart、mkfs、wipefs，以及 dd 向设备路径写入。该分类采取保守确认，某些查询或帮助调用也可能要求确认。
- PowerShell、CMD 和常见 POSIX Shell 的字面量命令可拆分检查；支持常见命令分隔符、嵌套 Shell、PowerShell UTF-16LE EncodedCommand，以及 sudo/env 等常见包装。可确定的内部命令也会匹配规则，外层 allow 不覆盖内层 forbidden。
- Python/Node/Dart 等解释器调用、脚本文件、动态变量、重定向、复杂表达式、未知 Shell 调用方式和超过分析深度的包装要求额外确认；常见的间接执行入口同样保守要求确认。

## 界面与结果

风险确认继续使用现有批准面板、字体、按钮和页面切换，不新增独立弹窗。卡片显示“命令需要额外确认”、风险说明、命中的规则，以及原有可执行文件、完整参数、实际工作目录和目的。内置说明和错误提供中英文，用户规则与实际命令保持原文。

拒绝规则、配置错误、缺少批准和等待期间规则变更返回稳定的结构化错误，分别为 command_forbidden、command_invalidRules、command_approvalRequired、command_changed。用时中的操作记录保留失败结果，界面将本地策略错误显示为当前语言，不标记成执行成功。

## 安全边界

这是命令调用检查，不是操作系统沙箱，也不是完整的 Shell 或通用编程语言解释器。它不能证明任意程序、脚本、别名、启动配置或子进程不会产生危险行为；默认情况下无法分析的调用需要人工审核，人工批准表示允许该调用及其后续行为；开启“命令免审批”后，由用户预先授权这些调用。forbidden 只拒绝可确定命中规则的调用，不保证识别等价脚本、程序改名或所有间接执行形式。

内置文件写入工具拒绝覆盖当前规则文件，但已获准运行的本机程序仍以当前系统账户运行，可能修改规则文件或其他文件。当前没有增加系统 ACL、提权、设备隔离或网络沙箱，不能把本功能当成对恶意本机程序的强安全边界。

## 回归验证

测试覆盖普通命令不误判、危险命令确认、字面量与参数边界、嵌套命令及编码脚本、规则严格优先级、仅开启能力授权时仍需确认、免审批下真实执行复杂脚本与 prompt 规则命令、免审批仍保留 forbidden、拒绝不启动、批准后真实执行、配置损坏和等待期间变更、模型伪造批准标记无效、规则文件写入保护，以及中英文深浅主题下的批准界面。真实删除仅在测试创建的临时目录内验证，不执行磁盘格式化或实际设备烧录。

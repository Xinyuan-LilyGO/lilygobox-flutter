# 提问卡片与回答回传

## 工具协议

模型通过 `request_user_input` 工具提出问题，由软件创建交互卡片。不是靠识别正文问号触发，也不需要模型厂商另提供专门的提问 API。Chat Completions 与 Responses 都沿用现有函数工具协议。

每次包含 1–3 个问题。每题有唯一的 `id`、简短标签 `header`、完整问题 `question`，以及 2–3 个带名称和说明的选项。推荐项由模型放在第一项；界面不预选，不代替用户回答。用户可以选择一个选项、输入自己的答案，或为所选项补充说明。所有问题均有答案后才可提交。

返回结构与 Codex 的答案映射保持一致：

```json
{
  "cancelled": false,
  "answers": {
    "target": {"answers": ["选择的选项", "可选的补充说明"]}
  }
}
```

答案按问题 ID 回传，关联本次工具调用的 ID，再由模型继续回复。取消返回 `cancelled: true` 和空答案；等待期间不猜测答案、不超时自动提交。无效问题结构不创建卡片，将工具错误回传模型。提问不授予文件、网络或命令权限，也不能代替请求批准。

参考本地 Codex：`codex-rs/core/src/tools/handlers/request_user_input_spec.rs`（工具格式）、`request_user_input.rs`（处理器）、`codex-rs/protocol/src/request_user_input.rs`（问题与答案结构）、`codex-rs/core/src/session/mod.rs`（等待及继续执行）。这里复用交互协议，不照搬 Codex 的计划模式限制。

## 显示位置与公共风格

等待回答时，卡片占据主聊天输入区的位置，与请求批准面板共用同一层级。通过现有 `PopupMenuPageTransition` 的 150 ms 渐变切换；离场内容禁止交互和获取焦点。不是覆盖在仍可操作的输入框上方，也不额外弹出模态窗口。

草稿、附件和待发送队列保存在输入区外部的原有状态中。进入提问时释放主输入框焦点；完成或取消后恢复原输入区，不丢弃草稿、不自动把答案当成新用户消息发出。

外框沿用批准卡片的主题表面、菜单阴影与圆角：外圆角 22 px、内圆角 17 px、外内层间距 5 px。主标题沿用 15 px、w600；字段标题与其下方问题说明直接复用编辑服务的 `AppDialogStyle.fieldTitleStyle`（13 px、w500、次文字色）和 `descriptionStyle`（11 px、1.4 行高、三级文字色）；权限申请卡片的字段标题与说明同样使用这组公共样式。内容复用已有菜单项与公共按钮，不新建独立配色。问题与选项随宽度自然换行。卡片按实际内容自然增高，整体最高占当前可用高度的 80%，不再套用批准卡片的 320 px 内容上限。普通单题在常规窗口下完整展示问题、选项和补充说明输入框，超长内容、多题或小窗口才在内部滚动；提交与取消按钮留在固定操作区域。标题左侧使用 fill 类型的帮助图标；滑块靠内层边缘 6 px，正文为滑块另留通道，禁止覆盖文字或控件。

停止生成、引导打断、销毁 provider 会解除等待并移除卡片；迟到的答案、重复提交或旧请求 ID 不得影响新请求。清空聊天沿用现有忙碌保护，生成中应先停止再清空。取消单次提问只向模型返回取消结果，停止生成则不继续发送模型请求。

“用时”详情记录等待回答状态及本次操作，完成后可展开查看可读的问题和答案；不把答案协议 JSON 作为错误详情展示。取消与工具失败分别记录，问题卡片不改变批准流程。

## 思考与正文分离

优先遵循 API 的结构化 reasoning 字段及 Responses reasoning 事件，将思考写入现有“模型思考”，正文写入聊天回复。Codex 的 `codex-rs/codex-api/src/sse/responses.rs` 也以事件类型区分两者。

部分兼容接口会将 `<thinking>…</thinking>` 或 `<think>…</think>` 放进正文开头。客户端额外做流式兼容：支持标签跨增量分片，仅将开头的思考块转入思考通道，流式显示与最终回复使用一致结果。普通正文中途的标签、代码围栏示例及其他 XML 保持原样；未闭合的思考块继续视为思考。此兼容不针对特定模型名称，也不修改系统提示词。Responses 的原始输出项仍供后续协议延续使用，包括加密 reasoning，不作为界面正文渲染。

相关规范：[权限与批准](assistant-permissions.md)、[回复与用时详情](assistant-response-details.md)、[提示框样式](dialog-style.md)。

反问选项同样按编辑服务的主次标签排版：选项名复用 `fieldTitleStyle`，说明复用 `descriptionStyle`，两者间距 4 px。普通状态保留次文字色与三级文字色；选中或悬停时随公共菜单项的前景色切换，不能将灰色文字固定在紫色背景上。

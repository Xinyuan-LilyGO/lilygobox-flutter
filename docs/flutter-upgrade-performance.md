# Flutter 升级与 Windows 性能验证

## 画布与长聊天卡顿

### 多选拖动时卡片脱离鼠标

按下时保存鼠标在卡片上的抓取点。拖动期间，每次指针移动或画布变换更新，都用**当前变换的逆矩阵**把屏幕指针换算到场景坐标，再扣除抓取点偏移。即使鼠标停住，滚轮平移和缩放动画也会改变这个换算结果。只在鼠标移动时累加位移，就会看见卡片落在指针后面。

大选区的卡片共用一个预览位移。部分选中时，分别查询移动组和固定组的可见区域，让刚从重叠处露出的卡片立即出现。松手时一次提交整个选区的位置，包括屏幕外的卡片，后台只排队保存坐标。拖动中按 Delete 先结束这次拖动，外部删除则清理未完成的拖动并保存其余卡片的位置。[工作流撤销与重做](assistant-workspaces.md#工作流撤销与重做)

### 上千张卡片的首次加载与平移

拖动松手时，撤销记录共享当时的回收站列表，回收站成员变化时才替换列表。仅改动坐标、画布原点或选中项时，存储线程单独更新这些字段。同一批还有工作流或聊天变更时按完整快照保存。回归场景使用 5,000 张回收卡，拖动后立即输入滚轮。

- **首次打开**数据库时显示不定进度，取得记录总数后按已恢复条数显示百分比，整理连接关系时再切回不定进度。恢复成功且数量为零时才显示「创建智能体」，读取失败且没有可显示的卡片时展示错误。按上级优先迭代恢复管理链，逆序存储的一万层关系也能加载，缺少上级或存在环时报告错误。
- 首次准备至少 512 张卡片时，按实际字体、语言和文字缩放**分帧测量**。每帧以 4 ms 或 256 张中先达到的一项为界，让出时间处理输入。进度只刷新加载区域，切走页面时暂停。重复标题复用测量结果，完整 ID 按实际换行高度布局。
- 超过 64 张卡片时，**空间索引**只查询视口及四周 96 个屏幕逻辑像素。完全重叠时优先挂载顶层两张及交互中的卡片，底层记录仍参与选择、移动和保存。缩小至 45% 进入概览，保留标题、角色、状态及连接端点，放大到 55% 以上恢复完整卡片。普通平移更新视图变换，右键菜单在打开时构建。
- **点阵和连线按批绘制**。点阵按缩放选择网格间距，复用坐标缓冲。Windows Skia 直接绘制概览卡片，Impeller 复用图像时每页像素缓存上限为 32 MiB。Skia 在预绘区有至少 64 条候选连线时，将普通曲线按 0.3 个物理像素的容差细分、分组绘制。命中测试、框选和通信动画使用原曲线。

### 长聊天滚动分两段或出现空白

滚轮目标可能超出当前已加载消息的边缘。边缘外还有历史时，应保留整次输入的目标位移，补入消息后继续同一段动画。测试在距分页边缘 20 px 时输入 100 px，以可见消息在屏幕上的实际位移验收，同时覆盖真正的首尾和反向滚动。

滚过预加载边界时，上方补入的消息会改变已挂载内容的总高度。若用新窗口的消息序号去解释上一帧的位置，下一帧就会反向校正，正文或滑块看起来像先走一段再追上。聊天分两层按需挂载，一层管理消息，一层管理单条长正文的区块。变更范围时，把同次布局的绝对序号和实际屏幕位置配对，以可见消息 ID 和它在视口中的偏移为锚，在绘制前校正滚动位置及正在进行的滚轮动画目标。滑块按整段历史定位，短 Markdown 直接显示格式化正文。[窗口边界、预加载与文字选择](scroll-behavior.md#聊天历史绘制范围)

缓存层与视口隔开时，移动缓存层会复用上次的画面。该层须包含已挂载子项的完整绘制，否则新露出的文字会留白。聊天底部在不透明背景上叠加渐变，让正文绘制层可以复用。[渐变与输入框阴影对照测试](../integration_test/chat_effects_performance_test.dart)

消息窗口限制挂载和绘制量，数据库仍按会话恢复完整记录。单条巨大表格或极长代码行的首次解析与布局需单独测量。

流式助手正文不按每个增量重建页面。正文和思考先写入 `StringBuffer`，只在界面刷新时生成完整字符串，避免每个 token 反复复制已有内容。正文刷新按长度采用约 16、100、200 ms 的节流，Markdown 解析在输出期间分段节流，结束时立即完成最终解析。流关闭、组件卸载和客户端取消均处理可预期的异步异常，避免流取消变成未处理异常。[同轮压缩与续写](agent-memory-storage.md) · [绘制前的底部跟随](scroll-behavior.md#聊天生成时的底部跟随)

Windows 原生中键阅读器的会话必须和 Flutter 视图一起结束。通道错误、视图卸载或窗口销毁时先发送停止请求并清理 Dart 会话，原生 runner 在模态阅读循环返回后再次校验 HWND，再恢复光标和发送消息。自定义消息绘制层在子节点失效或变换矩阵退化时回退默认绘制，避免把已卸载的 RenderBox 或无效坐标交给引擎。

长 Markdown 位于 `SelectionArea` 内时，消息窗口会按视口替换正文分段。替换期间保留一个稳定的语义容器，避免 Windows 无障碍桥在同一帧收到已脱离父节点的增量语义树。流式解析定时器在 State 停用时取消，重新挂载后再恢复，不能只用 `mounted` 判断 context 是否仍可更新。滚动窗口和自定义滑块读取 `ScrollPosition` 的像素或范围前同时检查单一 client、像素、视口和内容尺寸，窗口切换期间跳过未完成的布局帧。

长消息的无障碍节点跟随当前挂载的正文分段；滚动补载时，新分段的文字与链接随之进入语义树。保留每条消息的显式语义边界，不用截断摘要替代正文或移除链接操作。

上下文详情的左键浮层嵌套在右键菜单锚点内，两者必须由一个显式语义边界隔开。否则两个 `OverlayPortal` 的遍历锚点会合并，打开详情即可能让 Windows 的 `AXTree` 收到未连接的节点；加 `mounted` 判断不能修复这种原生错误。[真实窗口回归](../integration_test/chat_metrics_accessibility_test.dart)在最大化窗口中请求原生无障碍树，保持详情打开并让 Markdown 流跨过自动压缩阈值；用 `tool/test_window_accessibility.ps1` 同时校验测试结果和原生日志。

输入框要分别测**滚动、首次粘贴、持续编辑**。标准 `TextField` 持有全文，外层视口滚动时复用排好版的文字。粘贴经 `ReplaceTextIntent` 走编辑器的焦点、选区与撤销流程。文本、字号或宽度改变仍会触发整段布局。复测时包括中文输入法组合输入、全选复制和拖选越界滚动。[编辑器交互](text-input-style.md#特殊输入框) · [滚动与粘贴测试](../integration_test/chat_composer_performance_test.dart) · [持续编辑测试](../integration_test/chat_composer_editing_performance_test.dart)

### 仅在窗口最大化时明显变慢

普通窗口用透明背景合成圆角和自绘阴影。最大化或贴靠时，`AppWindowFrame` 将原生背景切为不透明并使用矩形硬裁剪，减少整窗合成开销，恢复普通窗口时切回透明。测试从原生窗口读取普通、最大化、还原、再次最大化四步的背景 alpha，依次应为 `0 → 255 → 0 → 255`。

Windows 主窗口在 runner 中通过 `DartProject::set_impeller_switch` 默认使用 Skia，托盘辅助进程独立配置。在同一台 GTX 960 上，用相同的完整程序、窗口和一万条聊天连续滚轮，按 Impeller、Skia、Impeller 的顺序测得每帧绘制耗时 P90 分别为 45.50、0.94、45.41 ms。升级 SDK 或换显卡后，用同一操作重测并核对报告中的 `renderer`。[Windows 入口](../windows/runner/main.cpp)

## 复现与验收

在项目根目录生成带编号的一万条聊天记录。包内含无换行长文本、千段 Markdown 和两千行代码，生成测试会用正式导入流程核对内容。先退出运行中的 LilygoBox（包括托盘），让原生测试取得单实例窗口。下面两次运行各用独立的内存数据库，3,000 或 10,000 张预置卡片在导入后各增加一张。

```powershell
flutter test --no-pub tool/long_chat_fixture_test.dart
$env:LILYGOBOX_MOTION_PACKAGE = (Resolve-Path 'artifacts/lilygobox-long-chat-10000.7z').Path
$env:LILYGOBOX_MOTION_CASE = 'both'
foreach ($cardCount in 3000, 10000) {
  $env:LILYGOBOX_MOTION_CARDS = "$cardCount"
  $env:LILYGOBOX_PERF_LABEL = "shell-$cardCount"
  flutter drive --profile --no-pub -d windows --driver=test_driver/workflow_performance.dart --target=integration_test/workspace_shell_motion_test.dart
}
```

驱动写入 `tmp/workflow-performance-<label>.json`。完整窗口从画布卡片进入导入的对话并保留无障碍。要定位组件开销，可在同一命令中换用独立组件入口并设置另一报告名。[完整窗口测试](../integration_test/workspace_shell_motion_test.dart) · [独立组件测试](../integration_test/workspace_motion_performance_test.dart)

把 `LILYGOBOX_MOTION_CASE` 设为 `loaded-chat` 可复测包含多份长聊天的工作区。它准备 25 个活动智能体，每个 10,000 条消息，另有 5,000 张回收卡。每张回收卡默认带 2 条短消息，`LILYGOBOX_MOTION_RECYCLED_MESSAGES` 可设置其消息数。在 `MSG-03630` 附近分别测单齿滚轮、连续跨页、暂停 145 ms 后继续滚动。中键用例要求按住拖动、短按后移动都使聊天产生位移，松开或按 Esc 后阅读位置稳定。报告同时记录帧耗时和同一条可见消息的屏幕位移，可用来区分慢帧与输入行程损失。

| 场景 | 验收方法 |
| --- | --- |
| 拖动时滚轮平移 | 全选、拖动、滚轮平移，然后保持指针静止直到动画结束。逐帧测指针和抓取点的距离、两张卡片的间距，最后核对所有保存坐标。部分选中的场景另查重叠处露出的卡片和连线端点。[画布交互测试](../test/features/assistant/task_topology_page_test.dart) |
| 长聊天滚轮与滑块 | 在 32 条与 10,000 条消息的相同尾部内容上发送相同滚轮输入，每 8 ms 取样，连续 40 帧的正文位移差应小于 0.01 个逻辑像素。完整窗口另查单次 100 px 的实际位移与连续 64 次输入跨越预加载边界时的方向。[正文位移测试](../test/features/assistant/chat_content_integration_test.dart) |
| 加载和帧耗时 | 分开记录冷启动到可见卡片的时间、16 ms UI 定时器最长回调间隔、交互期间的绘制耗时和松手后的保存。按动作时间窗筛选帧。排查主线程尖峰时查看包含 `flushSemantics` 的完整 UI 帧，`FrameTiming.buildDuration` 在提交场景时已结束。 |

2026-11-19 的**实测基线**取自开启无障碍的 Windows 最大化窗口。窗口为 2560 × 1540 物理像素，DPR 1.25，155 Hz，显卡为 GTX 960 2 GB，渲染后端为 Skia。P90 指 90% 的采样帧耗时不超过该值。

| 测量项 | 预置 3,000 张 | 预置 10,000 张 |
| --- | ---: | ---: |
| 首次恢复到卡片出现（导入前） | 0.61 秒 | 1.96 秒 |
| 加载中 UI 定时器最长回调间隔 | 64 ms | 73 ms |
| 25% 概览平移，绘制耗时 P90（导入后） | 9.48 ms | 14.00 ms |
| 70% 全选、拖动并滚轮，绘制耗时 P90（导入后） | 3.44 ms | 3.83 ms |

两组分别核对了 3,001 和 10,001 张卡片的最终位移，抓取点与组内间距的逐帧误差均低于 0.001 个逻辑像素。155 Hz 的单帧预算约为 6.45 ms，两组概览平移的 P90 均超过该预算。

在 3,001 张卡片的窗口打开测试对话，定位到第 5,521 条附近。一次 100 逻辑像素的滚轮输入让正文移动 100 逻辑像素，连续 64 次输入跨过约 105 条消息，绘制耗时 P90 为 0.92 ms。

| 最大化后首次打开设置卡顿 | 单独复测「最大化 → 操作画布 → 从个人中心首次打开设置」，再测重复打开。非 Web 的设置过渡短暂缓存背景和设置层，悬停时继续复用快照，点击、滚动或按键时恢复设置层实时绘制。[设置过渡实现](../lib/app/widgets/window_page_stack.dart) · [原生窗口性能测试](../integration_test/window_performance_test.dart) |

## Windows 窗口与升级检查

- **无边框窗口**初始化时设 `hasShadow = false`，保留应用的自绘阴影。打开系统文件对话框时处理 `WM_NCACTIVATE` 与 `WM_NCPAINT`，验证真实 HWND 的顶部像素。最小化时保留 Flutter 子窗口尺寸。最大化按钮投递原生消息切换窗口，移动或贴靠后再读取系统最终布局。[阴影测试](../integration_test/window_shadow_test.dart) · [系统对话框测试](../integration_test/modal_window_frame_test.dart)
- **Windows 冷启动闪白**：原生主窗口在 DWM 中保持不可见且可绘制，等 Flutter 首帧完成再显示和激活。Dart 启动阶段只配置窗口位置和样式，不提前显示。手动验证时完全退出应用（含托盘），从安装位置启动，检查屏幕左上角不会先闪出空窗口。
- **窗口拖动或改尺寸时闪白**：主窗口有 Flutter 子视图时不再用 Win32 背景刷擦除客户区，避免主题背景在下一帧之前覆盖画面。调整子视图时用 `SetWindowPos`，不强制同步重绘。回归测试用白色背景刷验证旧像素不被擦除，同时检查每次调整后视图尺寸与客户区一致。[原生重绘测试](../test/windows/window_repaint_native_test.cpp)
- **托盘窗口**由独立的 `trayMain` 进程承载，通过限制大小并校验对端的 `WM_COPYDATA` 与主进程通信。预热在可绘制的窗口完成，按 `requestId` 收到 `prepared` 后隐藏，用户打开时等 `painted` 再显示。隐藏期间缓存主题，Job Object 让辅助进程随主进程退出。回归实际切换主题、检查最终可见性，并在 Explorer 的隐藏图标面板手动右键一次。[托盘可见性测试](../integration_test/tray_visibility_test.dart) · [主题发布模式验证](../integration_test/theme_release_smoke.dart)
- **升级 Flutter** 时以依赖清单中的 SDK 与窗口库版本为准。Material 组件需要对应的本地化委托，SQLite 与压缩库通过 code assets 加载。升级后进行 `flutter analyze --no-pub lib`、存储回归和真实 Windows 窗口启动，原生 runner 改动需重新启动编译后的进程。[依赖清单](../pubspec.yaml) · [存储回归](../test/features/assistant/agent_storage_test.dart)

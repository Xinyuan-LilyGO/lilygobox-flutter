# AI 回复耗时与详情

模型选择菜单主体和模型项继续使用当前主题浮层实色；滚动时吸顶服务标题单独使用半透明浮层色，让下方经过的模型内容保持可感知，同时维持标题文字对比度。滚动条沿用全局自动显隐行为，不强制常显。列表右侧在滚动视口外预留 16 px，滚动条容器距菜单右沿 4 px（滑块外缘总距离仍为全局 6 px），模型项背景、文字和勾选图标不会被滚动条遮挡；局部使用 `AppScrollBehavior(scrollbars: false)` 保留平滑滚轮动画，并避免重复滚动条。

主页输入区的当前模型选择控件使用普通圆角矩形（8 px），与上方模型行保持一致，不使用全圆角胶囊；下拉箭头仍保留旋转动画，控件颜色和悬停状态继续复用当前主题。

每个处理段在对应正文顶部显示当前状态、计时和分隔线。首次请求尚未收到响应头时显示“正在连接”，收到成功响应、等待正文时显示“正在思考”，正文增量到达后显示“正在输出”。设置工具执行结束后再次请求模型时，显示“设置操作已结束，正在等待模型回复”，避免误认为尚未连接就执行了设置。准备设置操作、实际执行、重试、失败和停止分别显示对应状态；完成后显示最终用时。状态来自真实请求和工具事件，不根据等待时长猜测，也不在正文底部追加思考状态。

## 默认折叠的过程记录

“正在思考”阶段收到思考正文后，将该状态行直接合并为思考内容项，沿用阶段开始时间，不再并列显示两条。思考进行时标题为“正在思考”，图标固定使用 Material Symbols `neurology_rounded` 非填充样式（`fill: 0`）；合并为思考内容项后不依赖状态字段选择图标，避免字段为空时回退为圆点；标题转为“模型思考”后才切换为模型说明使用的点阵图标。未返回思考正文时保留原状态行。不使用带人头轮廓的 `psychology_rounded`；连接使用云同步图标，等待回复使用沙漏图标，输出使用编辑图标，工具准备使用设置图标，停止使用停止圆圈图标，重试使用刷新图标，完成使用勾选图标，失败使用错误图标，不再用无语义的圆点表示这些状态。

点击“用时／当前状态”行展开本轮过程，默认收起，不随请求阶段自动展开。展开后按事件实际发生顺序显示相对于当前处理段开始的时间、请求阶段、模型返回的思考内容、中途说明、设置操作的具体目标及成功／失败结果、后续请求和重试原因。顶部总用时和各过程项时间统一显示毫秒：小时未满时使用 `MM:SS:mmm`，达到一小时后使用 `HH:MM:SS:mmm`。模型思考内容使用与设备卡片相同的点阵图标；网页访问执行中与成功使用 Material Symbols `language_rounded` 非填充图标（`fill: 0`），状态显示“正在访问网页”，成功记录为“已访问网页 URL”，失败记录为“访问网页失败 URL”并保留原有填充错误图标（`fill: 1`）；网页访问不显示“正在修改设置”，也不叠加“已执行：”前缀。其他工具调用成功使用扳手图标，失败使用错误图标；各阶段状态使用对应语义图标，整轮完成使用勾。回合结束后不显示没有思考正文的“正在思考”状态项，实际收到的思考内容仍保留。过程较长时在最高 300 px 的详情视口内滚动，右侧内容预留 20 px 滚动条空间，滚动条外缘继续沿用全局 6 px 靠边间距，时间文字不贴住滑块；最终答复显示在过程区域之外。思考增量合并为连续段落，最多每 16 ms 通知一次界面更新。

Chat Completions 读取接口主动返回的 `reasoning_content`（或字符串形式的 `reasoning`）；Responses 读取推理摘要的流式事件和完成响应中的公开摘要。完成事件与增量重复的摘要不会追加两次。`encrypted_content` 不作为可读文本展示。模型或供应商未返回可展示的思考内容时，仅记录实际请求和操作事件，不生成、猜测或补写思考文本。

同一轮回复按“处理段用时与分隔线 → 正文 → 下一个处理段用时与分隔线 → 后续正文”的顺序排列。模型在正文之后调用工具时，冻结当前段的正文、状态、用时和过程记录，再创建新的处理段；工具执行、批准等待、后续模型请求和后续正文归入新段。没有正文间隔的连续工具调用共享同一处理段，不为每个工具创建空段。

各段分别计时，过程项时间从所属段开始计算；前一段定稿后不会继续增长，也不会被后续回复、失败或停止覆盖。“我查下当前时间”等 `content` / `output_text` 属于聊天正文，不放入思考记录；只有接口实际返回的 reasoning 字段作为模型思考。工具前后正文都保留在聊天记录与模型上下文中，不额外生成“模型输出”过程项。

分段不创建新的用户回合：整轮仍共用停止、继续、请求配置和队列调度。停止只冻结当前段，继续只接续最后停止的段；显式引导仍创建新的用户回合。设置结果明确显示成功或失败；没有执行操作时不额外显示提示。Chat Completions 的模型原始思考字段随对应助手消息回放，兼容需要工具上下文的推理模型；本地状态、耗时和过程记录本身不会发送给模型。

标准 SSE 响应按服务端增量立即显示，不再额外拆字或延迟播放；若兼容服务忽略流式请求并返回完整 JSON，正文一次显示。方形停止按钮取消当前 HTTP 请求和响应流，不提供本地暂停／恢复功能。停止后保留已显示的部分文本及已记录的思考、操作和重试过程。

客户端只合并同一轮队列中已经收到的文本，不设置人为输出间隔。收到结束信号且缓存处理完毕后立即进入完成状态，不等待打字动画；实际响应速度仍由模型服务和网络决定。

输出队列必须先登记异步任务，再开始消费增量。单字或分散到达的 SSE 增量可能立即排空，不能将已结束的任务重新登记为运行中，否则回复结束时会形成微任务循环并阻塞界面。回归测试须覆盖单字 JSON、间隔到达的单字 SSE，以及单字输出后的流中断。

计时在本轮完成、失败或停止后冻结。耗时覆盖用户发送到最终回复完成的全过程，包括助手发起的设置操作和后续模型请求。模型服务配置不会显示 API 密钥。

## 请求失败与重试

请求错误保存在对应轮次的消息中，显示“处理失败”和可复制的错误详情。即使没有收到正文也保留失败轮次；后续发送消息或修改模型服务不会清除之前的错误。错误和重试记录仅供界面展示，不作为助手回复发送给模型。会话仍按现有规则仅保存在内存中，清空会话或退出应用后不保留。

仅对未输出正文或工具调用的临时故障自动重试：网络请求异常、超时、HTTP 408、429 和 5xx。最多重试 2 次，默认分别等待 1 秒和 2 秒；服务端提供数字形式的 `Retry-After` 时使用该秒数，最长等待 30 秒。无效密钥、权限或参数错误不自动重试。显示“正在重试模型请求（当前次数/2）”，每次重试原因保留在本轮详情中。

收到正文或工具调用后发生的流中断直接结束为失败，保留已显示的正文，不自动重发，避免重复内容或重复执行设置。停止或销毁会话会取消等待中的重试，不作为请求失败展示。

## Markdown 与消息操作

聊天链接通过 `MessageLinkOpener` 调用系统默认程序：网页和邮件链接保留原有处理；本地 HTML（`.html` / `.htm`）支持 `file:` URI、Windows 绝对路径及 POSIX 绝对路径，先确认文件存在，再交给系统打开。仅含文件名的相对链接只匹配本段成功写入的唯一文件，不猜测工作目录。路径转换保留中文、空格和文件名中的特殊字符；URI 中的 HTML 锚点继续传给浏览器。无效、缺失或启动失败的链接统一使用 `showAppNotice` 显示本地化底部提示，不能静默忽略。

助手正文使用 `flutter_markdown_plus` 渲染常用 Markdown：标题、加粗、斜体、有序／无序列表、引用、行内代码、代码块、链接和表格。样式复用当前主题字段，表格按消息可用宽度分配列宽并换行。用户发送的正文保留原样，不将用户输入的 Markdown 符号转换为富文本。流式增量立即刷新正文，不添加打字播放。

用户消息发送后立即在正文下方显示复制图标和本地时间；助手回复仅在该轮完成、失败或停止后显示这组操作，生成中（包括连接、思考、输出及工具处理）不显示，避免把未完成回复表现为已结束。上方的用时和状态栏保持实时显示。时间格式固定为 `yyyy.MM.dd HH:mm:ss`，例如 `2026.11.09 15:22:32`。时间在消息创建时记录，流式更新和后续工具请求不会重置时间；该时间不作为模型上下文发送。只有实际记录过创建时间的消息才显示时间，不通过界面刷新时间补造历史时间。

聊天消息中的附件预览固定为 100 × 100 正方形；输入区附件最多每行 10 张，空间不足时按可读缩略图宽度减少列数，再均分当前行可用宽度，保持图片间距一致，超过两行在附件层内滚动。回到最新消息按钮的圆形背景为 28 × 28，箭头图标仍为 18 × 18。

复制按钮将原始正文写入剪贴板，保留 Markdown 标记、代码与换行；成功后短暂显示勾和本地化“已复制”提示。没有正文的失败回复可复制错误说明。聊天页的用户消息、助手正文、代码块、错误和展开的过程文字共用外层唯一的 `SelectionArea`，通过普通 `Text` 注册选区，右键菜单通过 `AppTextSelectionMenu.buildRegion` 复用统一公共菜单；不得嵌套独立 `SelectableText`，以免“全选”遗漏消息或代码。单击用时行切换展开或折叠时，清除聊天选区并关闭选择菜单；拖动选取文字不触发切换。用时标题始终可选定；折叠时仅排除隐藏的内部过程，展开后模型信息及过程文字也纳入选区。链接仅允许用户点击打开 HTTP、HTTPS 和邮件地址，打开失败显示本地化提示。

用户消息底部按“时间、复制按钮”排列，助手回复按“复制按钮、时间”排列。复制按钮静止底色与聊天背景一致，悬停使用 `interactionHoverColor(theme.secondary)` 从实际背景派生反向灰阶，浅色变深、深色变亮，避免固定悬停灰色融入页面。

代码围栏（包括 `text`、未指定语言和其他语言）显示独立圆角代码面板，顶部标注语言或本地化“纯文本”，右上角复制按钮只复制该代码块内容，保留缩进、尾部空格和换行，不包含围栏与语言标签。正文仍可通过统一选择区域选取，长代码行可横向滚动。行内反引号代码使用 4 px 圆角背景；`**加粗**` 仍按 Markdown 标准显示加粗文字。链接文字与下划线显式共用 `theme.basePrimary`，不从正文继承下划线颜色。

Windows 长消息选择需避免多个不必要的横向滚动选择容器：代码块按当前字体、缩放和可用宽度测量，能放下时直接加入消息的连续选区；超宽代码才使用横向滚动，但文字保持为普通 `Text` 并交给聊天页唯一的外层 `SelectionArea`，避免嵌套 `SelectableText` 截断跨视口拖选。横向滚动条保持可交互，拖选经过上下边缘时由外层消息滚动器继续滚动，保持复制进度。完整代码仍可通过代码块按钮复制。表格使用可用宽度分配列宽，不再为每张表添加横向滚动选择容器。回归覆盖 Windows 下滚动长回复后选择第二个代码块、表格，以及跨普通代码块选择。

聊天记录距离底部超过 120 px 时，在输入区右上方显示“回到最新消息”按钮；点击后平滑滚至底部，并在接近底部时隐藏。按钮随输入区实际高度定位，空会话不显示；系统关闭动画时直接跳转，不强制聚焦编辑器。

按钮可见性同时监听主聊天列表的滚动位置和 `ScrollMetricsNotification`：流式内容增高、图片加载或窗口改变后，必须按最新布局重新计算。用户仍在底部时，模型输出、图片加载和布局增高会自动平滑跟随最新内容；用户主动向上滚动时立即暂停跟随（不等待超过 120 px），回到底部或点击按钮后恢复。忽略代码块和详情等嵌套滚动区域的尺寸通知。

该按钮使用主题的 `iconBackgroundColor` 中性填充，悬停从实际按钮底色派生，保持明暗主题下与页面的区分。出现和收起仅使用 150 ms 透明度淡入／淡出，保持控件坐标和尺寸固定，不展开、不缩放、不平移；隐藏过程中立即退出鼠标、键盘和无障碍交互，系统减少动画时立即切换。

聊天记录和聊天编辑器统一使用 `AppScrollBehavior(scrollbars: false)`，只由各自外层绘制一根滚动条，仍保留全局 180 ms 鼠标滚轮平滑动画、连续滚轮目标累计和嵌套滚动仲裁。不能用 `copyWith(scrollbars: false)` 替代：Flutter 会跳过 `buildScrollbar`，连同平滑滚轮入口一起关闭。

## 透明图标按钮的悬停过渡

消息及代码块复制按钮复用 `TitleBarIconButton` 和 `InteractionDecoration`，保持共用的 150 ms 线性悬停动画和点击水波纹。透明静止背景必须使用悬停目标颜色的 RGB，并将 alpha 设为 0；进入和移出时只改变透明度。不要直接将透明黑 `Colors.transparent` 与不透明悬停色作为动画两端，否则 RGB 和 alpha 同时插值，叠加到页面后会短暂变暗，看起来像闪色。

调用方仍可传入 `Colors.transparent`，由共用按钮统一规范化。禁用和窗口失焦状态保持透明，不额外绘制圆形背景；切换主题立即更新配色，不播放旧主题颜色。系统减少动画时直接切换。回归测试须覆盖明暗主题的进入、移出中间帧，不能只检查动画起点和终点。

## 含图片消息的回到底部

聊天列表采用懒加载，不同高度的文字和图片消息进入视口时，`maxScrollExtent` 可能重新估算。“回到最新消息”不能只使用点击时的单次估算值：到达目标后等待布局更新，仍有剩余距离则继续校正，使用原有平滑动画；减少动画时直接定位后复查。校正须有次数上限，页面卸载、新的定位请求或用户中途取消滚动时结束，避免持续输出时无限追随或抢占用户滚动。回归覆盖混合高度图片消息、输入区带图片附件，以及开启／关闭动画时单次点击到达底部。

## 输入区多图附件预览

输入区保留双层结构：外层背景使用 `Color.alphaBlend(theme.primary.withValues(alpha: .42), theme.secondary)`，文字输入区使用 `theme.primary`。外层背景的阴影复用右键菜单 `PopupMenuSurface.shadowsFor(theme)`，保留外层 22 px 圆角，随主题进度平滑过渡；不在内层文字输入框重复叠加阴影。草稿附件直接放在外层承载区中、文字输入区上方，不增加独立附件卡片。仅当待发送队列与草稿附件同时存在时，在两者之间显示 1 px 分割线，使用现有 `theme.dividerColor`，左右各缩进 12 px，分割线上下各留 8 px 对称间隙，队列项之间统一使用 5 px 间距，最后一项不保留尾部间距，同时移除相邻队列底部与附件顶部的额外留白；队列列表底部到分割线、分割线到附件列表顶部的实际间距均为 8 px，留白固定在滚动区域之外，不随内容滚走；只有队列或只有附件时不显示分割线。分割线统一使用全局主题色：暗色 `dividerColor` 为 `#505050`，浅色为 `#D0D0D0`；其他共用该字段及 Material `outline`／`outlineVariant` 的分隔与边框同步生效，不在附件区域单独覆盖颜色。保留原有高度展开动画、缩略图计算和独立滚动。缩略图为等边正方形，边长不超过 64 px，间距 8 px。扣除左右各 12 px 的对称内边距后，按 `列数 = ceil((可用宽度 + 8) / (64 + 8))`、`边长 = (可用宽度 - 8 × (列数 - 1)) / 列数` 计算，让完整行填满可用宽度；不足一行仍保持相同尺寸，不拉伸填充。附件区最大高度为两行图片、行间距和上下各 7 px 内边距之和；更多图片使用独立纵向滚动，支持共用平滑鼠标滚轮和可拖动滚动条。滚动条沿用全局显示／隐藏规则，不强制常显；滚动条位于右侧 12 px 留白内，不额外增加右边距，避免两侧留白不一致或覆盖图片及移除按钮。禁止仅用无滚动提示的单行横向列表裁切大量附件。附件高度变化保留扩展动画，系统减少动画时直接更新。

发送后的图片使用 120 × 120 px 正方形预览、8 px 圆角，按原比例完整缩放（`BoxFit.contain`），空余区域使用当前主题的 `secondary` 背景填充，不裁切截图内容；不与输入区最大 64 px 的附件缩略图共用尺寸。

## 原图预览

发送后的图片与输入区附件共用 `ImageClipboardMenu`：右键菜单提供“查看原图”和“复制图片”，双击缩略图也可打开原图。预览使用共享的 `showAppImageViewer`，按原比例完整展示原图字节，不使用缩略图作为预览数据。

遮罩沿用应用弹窗的 `DialogTheme.barrierColor`，未配置时使用 Flutter 标准的 `Colors.black54`。打开和关闭仅进行共用的 150 ms 透明度渐变，图片解码完成后淡入；系统减少动画时立即切换。右上角关闭按钮复用 `TitleBarIconButton` 和统一悬停提示。点击图片以外的区域、关闭按钮或按 Escape 退出；点击图片本身不关闭，拖动图片不触发关闭。

按住 Ctrl 并滚动鼠标滚轮，以鼠标位置为锚点缩放，范围为初始适配尺寸的 0.25～8 倍；普通滚轮不缩放。可拖动平移查看放大后的内容，每次重新打开恢复初始适配状态。相关按钮、菜单和加载失败提示使用本地化文案。

## 待发送队列与立即引导

AI 正在回复或执行设置操作时，发送补充说明或图片会先加入待发送队列，不立即打断当前任务，也不新增独立用户消息气泡。输入区有内容时右下角显示“加入队列”，清空后恢复停止按钮；回车发送保留输入焦点，鼠标发送不自动聚焦。

队列位于双层输入框之间，与图片附件使用同一承载区。顶部固定显示队列名称与条目数量，标题位于滚动区域之外；只有下方条目列表滚动，滚动条也仅覆盖条目区域。每条显示正文摘要、图片缩略图，以及编辑、立即引导和移除按钮。多条消息按加入顺序排列，区域最高 160 px，超过后使用共用滚动行为及滚动条，不挤占正文输入区。高度变化沿用扩展动画，减少动画时直接更新。

队列使用 `theme.assistantQueueSurfaceColor`，直接复用 `theme.primary`，与内层文字输入区保持相同背景，不加边框，随主题渐变。图标按钮复用公共圆形控件（25 × 25，图标 15 × 15），静止背景透明，悬停从队列实际背景派生，不能用紫色透明叠加或另一层背景的悬停色。

### 编辑与取消

点击编辑后将该条消息从队列取回主输入框，同时恢复文字与图片附件，并聚焦主输入框；不再提供队列内编辑框、保存或取消编辑按钮。若主输入框已有草稿，取回文字在前、已有文字在后（换行分隔），图片同样保留并合并，避免覆盖草稿。用户修改后通过主输入框重新发送；运行中发送会重新排到队尾，空闲时直接发送。取回的内容不参与队列自动发送，其余排队消息仍按原顺序正常处理。叉号移除整条排队消息。

### 自动发送与立即引导

普通队列等待当前任务完整结束，包括所有设置工具及其后续模型请求，才按顺序一次提交一条。不能在单个工具调用结束后提前消费队列。每条处理完成后再发送下一条，不合并为一个请求、不并发调用模型。任务处理期间固定使用该轮开始时的服务、密钥、模型和思考强度；图片能力校验同样以本轮模型为准。

点击某条的“立即引导”会优先提交该条，其他条目继续等待。Chat Completions 和 Responses 不向已经发出的 HTTP 请求追加输入：先真正取消当前请求与响应流，保留已经收到的正文、过程记录和已完成的设置操作，再串行发起携带引导的新请求，接续同一轮任务；不把此中断记录为网络错误或用户停止。正在执行的单个设置操作允许结束，其余未执行工具以取消结果闭合上下文。空闲时该按钮直接发送所选条目；停止后则接续已停止的任务。

仅手动点击“引导”的消息从队列移除后，会先结束当前请求并保留已经显示的助手回复及其上下文，再作为普通用户消息加入聊天记录，随后创建新的助手回复、计时和过程记录。上一回合的正文不会移入用时详情；引导内容也不会再作为用时中的过程事件显示。取回主输入框的草稿不再属于队列，只有用户再次发送后才参与后续请求。

请求失败或停止时不自动发送剩余队列，保留内容供编辑、手动发送或移除。清空会话同时清除队列和编辑状态。队列与聊天记录一样只保存在内存中。

停止生成后保留该轮已累计用时、所有状态记录、模型思考、已输出正文和操作记录，标记为“已停止”。即使尚未收到正文、只有连接或等待状态，也不得删除该轮及其用时详情。停止后计时冻结，继续生成时接续原轮次与过程记录，不清空历史，不显示为网络错误，也不自动重试或启动后续模型请求。已经完成的设置操作不回滚；正在执行的单个操作允许结束，其余工具以取消结果闭合上下文。停止后重新发送会发起新的请求，不恢复旧连接。

停止结束且输入区为空时，右下角显示“继续生成”的三角图标。点击后以当前选择的模型服务发起新请求，继续同一轮任务；保留原轮次身份、创建时间和过程记录，计时继续累计且不包含停止后的等待时间。没有新引导时保留此前正文并直接追加续写；明确接入新引导时，前一阶段回复收入折叠过程。若存在待发送队列，先提交队首消息，再按顺序处理剩余消息；否则加入仅供模型使用的继续任务指令。普通输入内容或附件存在时显示发送按钮，按新消息处理；清空会话会清除继续入口。该操作不恢复已经取消的网络连接，也不重新执行已完成的工具。

## 停止后续写的正文完整性

无新引导时点击继续，保留停止前的原始正文，将新请求返回的增量逐字节意义上的文本顺序直接追加到正文，不插入换行或重新打开 Markdown 代码围栏，也不将旧正文移入过程记录。再次停止和继续仍沿用同一消息及完整前缀；复制按钮复制合并后的完整正文。上下文只记录每次请求实际新增的文本，不能把用于显示的累计前缀重复发送。有新引导时按新阶段处理，上一阶段回复仍保留在过程记录。

过程区域只显示实际收到的模型思考、状态、工具操作和重试记录；助手正文保持在正常聊天消息中，不拆成“模型输出”过程项。

### 自动排队消息与手动引导的区别

未点击“引导”的队列项，在当前整轮（包括工具链）成功完成后按顺序作为普通用户消息发送。每条保留文字和图片、独立显示在聊天记录中，随后创建新的模型回复与独立计时、状态和过程；不写入“用户引导”折叠项，也不折叠上一轮最终正文。自动发送采用发送时选中的模型配置。只有手动点击“引导”才接入当前轮次；停止、失败或销毁后不自动消费剩余队列。

第一层文字输入框的内边距、编辑区与底部工具栏之间的空白均可通过单击聚焦主文本输入框。第一层通过 `TextFieldTapRegion` 归入文本输入区域，空白按下通过 `onTapDown` 请求焦点，长按期间不得先失焦再在松开后恢复；子控件优先处理各自手势；附件、模型选择、发送、停止等按钮不能因父级点击处理而自动聚焦输入框。回车发送继续保留焦点，鼠标发送不自动恢复焦点。

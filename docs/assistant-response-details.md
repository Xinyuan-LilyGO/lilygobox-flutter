# AI 回复耗时与详情

每轮回复在正文顶部显示当前状态、计时和分隔线。首次请求尚未收到响应头时显示“正在连接”，收到成功响应、等待正文时显示“正在思考”，正文增量到达后显示“正在输出”。设置工具执行结束后再次请求模型时，显示“设置操作已结束，正在等待模型回复”，避免误认为尚未连接就执行了设置。准备设置操作、实际执行、暂停、重试、失败和停止分别显示对应状态；完成后显示最终用时。状态来自真实请求和工具事件，不根据等待时长猜测，也不在正文底部追加思考状态。

## 默认折叠的过程记录

“正在思考”阶段收到思考正文后，将该状态行直接合并为思考内容项，沿用阶段开始时间，不再并列显示两条。思考进行时标题为“正在思考”，转入其他阶段后改为“模型思考”；未返回思考正文时保留原状态行。

点击“用时／当前状态”行展开本轮过程，默认收起，不随请求阶段自动展开。展开后按事件实际发生顺序显示相对于本轮开始的时间、请求阶段、模型返回的思考内容、中途说明、设置操作的具体目标及成功／失败结果、后续请求和重试原因。顶部总用时和各过程项时间统一显示毫秒：小时未满时使用 `MM:SS:mmm`，达到一小时后使用 `HH:MM:SS:mmm`。模型思考内容使用与设备卡片相同的点阵图标；工具调用成功使用扳手图标，失败使用错误图标；普通进行中状态使用实心圆点，整轮完成使用勾。回合结束后不显示没有思考正文的“正在思考”状态项，实际收到的思考内容仍保留。过程较长时在最高 300 px 的详情视口内滚动，右侧留出滚动条空间；最终答复显示在过程区域之外。思考增量合并为连续段落，最多每 16 ms 通知一次界面更新。

Chat Completions 读取接口主动返回的 `reasoning_content`（或字符串形式的 `reasoning`）；Responses 读取推理摘要的流式事件和完成响应中的公开摘要。完成事件与增量重复的摘要不会追加两次。`encrypted_content` 不作为可读文本展示。模型或供应商未返回可展示的思考内容时，仅记录实际请求和操作事件，不生成、猜测或补写思考文本。

同一轮中的多次模型请求共享一份过程记录；工具调用前的助手说明归入过程，后续答复不会将它覆盖丢失。设置结果明确显示成功或失败；没有执行操作时不额外显示提示。Chat Completions 的模型原始思考字段随对应助手消息回放，兼容需要工具上下文的推理模型；本地状态、耗时和过程记录本身不会发送给模型。

标准 SSE 响应按服务端增量立即显示，不再额外拆字或延迟播放；若兼容服务忽略流式请求并返回完整 JSON，正文一次显示。暂停会暂停网络接收和待显示文本，继续后立即显示已缓存内容。停止后保留已显示的部分文本及已记录的思考、操作和重试过程。

客户端只合并同一轮队列中已经收到的文本，不设置人为输出间隔。收到结束信号且缓存处理完毕后立即进入完成状态，不等待打字动画；实际响应速度仍由模型服务和网络决定。

输出队列必须先登记异步任务，再开始消费增量。单字或分散到达的 SSE 增量可能立即排空，不能将已结束的任务重新登记为运行中，否则回复结束时会形成微任务循环并阻塞界面。回归测试须覆盖单字 JSON、间隔到达的单字 SSE，以及单字输出后的流中断。

计时在暂停时冻结、继续后累计。耗时覆盖用户发送到最终回复完成的全过程，包括助手发起的设置操作和后续模型请求。模型服务配置不会显示 API 密钥。

## 请求失败与重试

请求错误保存在对应轮次的消息中，显示“处理失败”和可复制的错误详情。即使没有收到正文也保留失败轮次；后续发送消息或修改模型服务不会清除之前的错误。错误和重试记录仅供界面展示，不作为助手回复发送给模型。会话仍按现有规则仅保存在内存中，清空会话或退出应用后不保留。

仅对未输出正文或工具调用的临时故障自动重试：网络请求异常、超时、HTTP 408、429 和 5xx。最多重试 2 次，默认分别等待 1 秒和 2 秒；服务端提供数字形式的 `Retry-After` 时使用该秒数，最长等待 30 秒。无效密钥、权限或参数错误不自动重试。显示“正在重试模型请求（当前次数/2）”，每次重试原因保留在本轮详情中。

收到正文或工具调用后发生的流中断直接结束为失败，保留已显示的正文，不自动重发，避免重复内容或重复执行设置。停止或销毁会话会取消等待中的重试，不作为请求失败展示。

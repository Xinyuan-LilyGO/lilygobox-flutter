# LilygoBox 局域网设备连接

## 当前范围

当前支持 Flutter 与 T-Display-P4 的真实连接，包含自动发现、首次设备确认、授权保存、断线自动重连、设备信息读取及心跳。AI、投屏、亮度和 Radio 控制均未接入。

连接采用 UDP 发现和 TLS 加密的 WebSocket。每台设备首次启动连接服务时生成独立的 ECDSA P-256 密钥与自签证书，保存后重复使用；应用在配对成功后将证书的 SHA-256 指纹保存到系统安全存储，后续连接必须匹配。无需云端服务器或付费证书。

首次配对采用首次使用信任（TOFU），需要在可信局域网完成并在设备上确认。TLS 保护传输内容，但首次配对尚未通过独立渠道验证设备身份，不能完全防止首次连接时的中间人攻击。设备名称和 MAC 地址仅用于识别目标，不能替代身份验证。

设备最多保存五份应用授权，每份使用独立的随机 256 位连接密钥。重连通过随机挑战和 HMAC-SHA256 双向证明恢复授权，授权消息和业务数据均在 TLS 连接内传输。应用端使用系统安全存储，设备端使用独立 `app_nvs` 分区；应用授权采用 TLV 存储，TLS 身份作为独立记录持久保存。不涉及 GitHub 账号令牌。

## 实机操作

1. 使用 ESP-IDF 编译并烧录 LilygoBox 设备固件。固件配置需启用 `CONFIG_HTTPD_WS_SUPPORT=y` 和 `CONFIG_ESP_HTTPS_SERVER_ENABLE=y`，默认配置由 `sdkconfig.defaults` 提供。
2. 设备通过 WLAN 连接路由器；Windows 电脑连接同一可互通的局域网。有线连接电脑也可以，不要求访问互联网。
3. 设备上进入 **Settings → More Connections → LilygoBox App**，开启 **Auto-connect**。未开启 WLAN 或尚未获得局域网地址时，开关仍保持开启并保存偏好，公共提示框提醒开启 WLAN 或连接网络；网络恢复后自动继续，无需互联网访问。开关和授权会持久保存，退出设置后仍保持后台发现；关闭开关会停止发现并断开当前会话，保留授权。
4. Windows LilygoBox 首页点击 **添加设备**，根据名称和 MAC 地址确认目标设备后点击连接。搜索结果会排除已添加的设备。
5. 首次连接时设备通过公共提示框显示请求，点击 **Allow**。已授权应用后续自动重连，无需重复确认。Flutter 校验设备的 ready 消息并保存配对信息后，添加页显示 **连接完成**，展示设备名称、型号、MAC 和当前 IP 地址。点击 **返回主页** 回到设备列表，不自动跳转，也不弹出连接成功通知；添加期间在后台恢复的连接也会显示完成页，已有连接的心跳不会中断添加其他设备。
6. 点击主页中的设备卡片，查看 MAC 地址、型号、IP、固件版本和运行时间。运行时间随心跳更新。主页设备卡片显示在线状态、连接方式和 MAC 地址。
7. 切换 Flutter 的主页或设置，已建立连接应保持。设备端切换页面不影响连接或发现，首次确认由全局 UI 管理；锁屏、开机及电源菜单期间不展示授权弹窗。
8. **LilygoBox App** 页面中的 **Current connection** 显示当前连接的应用名称，未连接时显示 **Not connected**。已连接时右侧显示蓝色 **Disconnect**，点击后需确认；断开会通知 Flutter 停止自动重连，保留授权和排序，再次在 Flutter 手动连接可恢复。设备运行期间会记住该应用的暂停状态，防止通知丢失或应用重启导致立即重连；重新开启设备 Auto-connect 或重启设备可清除此暂停状态。进入 **Authorized apps** 管理页面，拖动最左侧的 Material Menu 三横线图标调整优先级；名称过长时使用 LVGL 循环滚动。每台设备最多保存 5 份独立授权，列表顺序重启后保留。列表按钮统一为红色 **Delete**，确认后删除指定授权，若该应用当前已连接则同时断开，无需先手动断开；保存失败时保留授权和连接。授权已满时先删除一项再添加。在 Flutter 点击 **断开连接** 会暂停本次应用运行期间的自动重连，保留授权；点击重试或重启应用可恢复。直接断电/网络无响应时，约 15～20 秒内判定离线。
9. 网络中断后，Flutter 会自动按稳定设备 ID 重新发现地址并恢复连接，支持设备 IP 变化和两端重启。清除授权后需用户手动发起连接并在设备上确认。添加另一台应用前，请先在当前 Flutter 主动断开连接，避免后台重连占用设备。

设备端断开与删除确认框的主按钮统一使用蓝色。WLAN 和应用凭证都可直接删除：确认后移除已保存信息，若当前已连接则同时断开。应用的单独断开操作位于 **LilygoBox App** 页面。

Flutter 主页支持右键点击设备卡片，选择 **删除设备**，确认后清除该设备的本地资料、配对令牌、证书指纹和自动重连缓存；若该设备正在连接或已在线，同时结束其会话。取消确认不会修改设备配置或连接。删除其他设备不会断开当前连接。删除成功后显示提示，保存失败时保留卡片并提示重试；重新添加已删除设备需要再次在设备上授权。此操作只清理桌面端，设备端保存的应用授权仍需在 **Authorized apps** 中删除。应用安装标识独立保存，删除设备不会清除；重新添加并在设备端确认后，设备更新同一条授权、轮换密钥并保留优先级，不增加凭据数量。

当前优先验证 Windows 与 T-Display-P4。Android 尚未完成实机权限、后台生命周期及广播可达性验证；浏览器不支持本版 UDP 发现。

## 协议 v1

- UDP 发现端口：18463。Flutter 从本机各 IPv4 网卡的临时端口发送广播，设备向请求来源单播响应。
- 加密 WebSocket：`wss://<设备 IP>:18464/api/v1/ws`。客户端要求 TLS 连接，不自动降级为明文通信。
- 消息使用 UTF-8 JSON，公共字段 `v: 1`、`type`；设备响应包含 `deviceId`。
- `deviceId` 使用 ESP 出厂基础 MAC 的 12 位小写十六进制；界面以 `AA:BB:CC:DD:EE:FF` 格式显示 MAC。它用于区分设备，不是授权凭证。
- 发现请求：`{"v":1,"type":"lilygobox.discover","nonce":"本轮随机字符串"}`。
- 发现响应：`lilygobox.device`，原样回传 nonce，并包含 deviceId、name、model、firmware、port、`transport: "wss"`。客户端只使用 UDP 报文来源作为设备地址；发现信息不决定证书信任。
- 会话顺序：`hello`（deviceId、clientName、clientId、pairingVersion: 2）→ `waiting` → 客户端每秒 `poll` → 设备确认后 `ready`。
- `clientId` 是桌面应用独立持久化的 64 字符小写十六进制随机安装标识，不是配对密钥，也不是电脑名称。它只用于人工确认后的记录更新，不能代替 HMAC 认证。同一安装重新配对时原位更新凭据；五个名额已满时仍可更新自己的记录，不覆盖其他应用。
- 首次确认后 `ready` 包含 name、model、firmware、uptimeMs、pairingToken；凭据持久化后才发送，发送成功后设备才标记已连接。不要把 pairingToken 写入日志。
- 自动恢复：`hello` 增加 `resume: true` 和 `pairingId`（pairingToken 的 UTF-8 字节的 SHA-256，小写十六进制公开标识） → `challenge`（64 位十六进制随机 challenge、设备 proof）→ `authenticate`（应用 proof）→ `queued` → 每秒 `poll` → `ready`。HMAC 的 key 是 pairingToken 的 UTF-8 字节，消息为 `server|deviceId|challenge` 或 `client|deviceId|challenge`，输出小写十六进制 SHA-256。
- `hello` 包含 `automatic`：后台重连为 true，用户手动连接为 false。设备主动断开使用 `disconnected` 消息；Flutter 只在已连接或已验证设备证明后接受，保留密钥并暂停重试。暂停后的自动握手完成认证后仍返回 `disconnected`，手动握手通过认证才解除暂停。
- `upgrade_required` 表示配对协议不兼容，应用保留授权并停止自动重试；更新 Flutter 和固件后手动重试。握手必须包含 `pairingVersion: 2`。
- `authorization_revoked` 表示授权已清除或不匹配；应用删除对应凭据并停止自动重试，不自动弹出新的首次授权请求。
- 已连接后客户端每 5 秒发送 `ping`，设备返回 `pong` 和信息快照。15 秒无有效心跳后清理会话。
- 确认最长等待 60 秒。取消、超时、页面销毁或身份不匹配均不能将迟到响应变成成功连接。
- 最多保存 5 份授权；允许有限数量的候选握手，但仅有一个正式控制连接、一个首次确认弹窗。
- 从首个通过身份验证的候选开始收集 4 秒，设备按持久化顺序选择窗口内在线的最高优先级应用。未在线的应用不会阻塞后续候选；已连接后更高优先级上线不抢占，修改排序也不会打断当前连接。
- `queued` 是等待设备仲裁，不能当作首次授权或已连接。`busy` 表示其他应用占用，Flutter 保留凭证并稍后重试。`pairing_full` 表示五个名额已满，不能静默覆盖已有记录。
- 首次人工确认优先于后台重连候选。每份授权使用独立随机密钥；名称仅用于展示，不能作为身份或排序依据。UI 只读取公开标识、名称和连接状态，不读取或显示密钥。
- ESP 端使用 `app_nvs/settings/app_connections` 保存开关及有序授权列表，采用嵌套 TLV 结构：外层 enabled=1、credential=2（重复记录）；每条记录 id=1、token=2、clientName=3、clientId=4（可选，兼容已有记录）。
- 未知消息、错误版本、分片文本和大于 1024 字节的输入会被拒绝。

控制协议与发现服务已分离，后续可以替换或补充 mDNS 发现，不必修改页面流程。

## 排查

- 同一电脑反复出现授权弹窗：确认应用能够读写系统安全存储，并检查两端配对协议是否一致。`hello` 必须包含 `pairingVersion: 2`，重连包含 `pairingId`。应用名称仅用于显示，同名不代表同一份授权。两端更新后，已有凭据会在密钥认证成功的重连中补记 clientId；建议先正常重连一次，再测试删除和重新添加。以前已失去配对密钥的重复记录无法安全自动合并，可在设备的授权列表手动删除。清空应用的全部安全存储会重置安装身份。
- 未发现：确认设备 Auto-connect 已开启并获得 WLAN 地址，两端不是隔离的访客网络。
- Windows 防火墙提示时，只在受信任的专用网络允许应用通信。不要关闭整个防火墙。
- VPN、多网卡或路由器 AP 隔离可能影响广播；连接同一 SSID 也不一定表示客户端之间可互通。
- 确认服务已经启动：系统日志包含 `Local discovery and encrypted WebSocket ready`。固件使用项目统一的 `LogMessage` 接口输出连接日志，不记录私钥或配对密钥。
- 提示设备身份变化：连接会停止，已保存的证书不会自动替换。仅在确认设备确实已重置后点击 **重新配对**，通过确认弹窗清除本地信任，再到设备上允许连接。
- 设备证书保存失败或记录损坏时，加密服务不会启动，也不会自行替换身份。检查设备存储和日志。
- 不能确认：解锁设备，检查是否出现公共 Allow 提示；拒绝或超时后重新发起。

## 验证边界

自动测试使用真实回环 UDP/TLS WebSocket 检查发现过滤、身份检查、确认流程、心跳超时、取消竞态、授权持久化、自动重连、地址变更、撤销授权和伪造挑战拒绝，并验证证书变化拒绝、证书保存失败及明文连接拒绝。测试证书仅用于回环测试，设备运行时生成自己的密钥。回环测试不代表设备无线链路已经实测通过。

TLS 握手只发生在建立连接时，已连接后的指令和心跳共用同一条加密通道。服务串行执行握手，单次握手限时 3 秒，最多保留六条候选或活动会话；实际内存占用、握手耗时和大流量吞吐量需要在设备上测量。

### 五应用优先级回归

- Flutter：`flutter test test/features/devices test/app/navigation/page_retention_test.dart`，覆盖公开标识、优先级等待、占用重试、满额拒绝及取消竞态、设备主动断开保留授权、手动恢复、协议不匹配保留凭证及多次重启只授权一次。
- 实机建议：两台应用分别授权后都退出；将 B 拖到 A 前面，重启设备并同时打开 A/B，检查 LilygoBox App 页的 Current connection 显示 B。完全退出 B 应用后检查 A 自动连接；再启动 B，确认不会抢占 A。检查横竖屏拖动、排序重启保留、外层断开保留授权，以及列表删除当前应用时同时断开且不再自动申请授权。

### 删除后重新添加回归

- 同一桌面应用连续删除、重新添加三次：每次设备端需重新确认，确认后凭据数量及优先级保持不变，旧密钥失效。
- 凭据达到五份时，同一应用仍可确认并更新自己的记录；第六个新应用应被拒绝。
- 两个安装标识不同但电脑名称相同的应用应保留独立记录。
- 拒绝、超时或存储失败时，设备原有凭据和排序保持不变。
- 普通断线和应用重启仍走已有密钥的挑战应答，不重复弹出授权确认。

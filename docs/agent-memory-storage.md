# 智能体记忆、聊天存储与数据包

## 使用入口

设置 → 智能体 → 存储位于模型服务下方。工作流卡片的右键菜单也提供管理聊天记录与上下文、导入长期记忆包、导出长期记忆包、导出聊天记录与上下文包和导出智能体包。聊天页不再放置重复的清空按钮；清除某个智能体的聊天记录在存储页确认后执行。

记忆仅归属于独立智能体，已删除智能体的记忆随完整会话保留在回收站。共享记忆功能已移除，不读取、迁移或清理旧共享范围的数据。已删除智能体通过回收站保留完整快照，可恢复或永久删除。记忆列表每页 50 条，可搜索、编辑、删除；条目右侧提供编辑按钮，直接打开当前记忆的编辑窗口，不提供历史版本功能。数据库仅创建当前数据表，不读取、迁移或清理旧 `memory_versions` 表；保存、复制、读取和导入导出均只处理当前记忆，不记录历史正文。当前记忆的 ID、内容哈希、lineage、修订号和基准哈希继续用于定位与冲突校验，不代表保存历史版本。清除聊天保留长期记忆。

## 本地持久化

Windows 数据库：

```text
%LOCALAPPDATA%\LILYGO\LilygoBox\data\main.db
```

工作流数据格式与导出包 manifest 的版本号均从 1 开始。仅接受当前格式；不读取或迁移旧偏好中的工作流、不补造旧聊天消息 ID 或模型历史。测试可使用不持久化的内存会话，正式应用统一使用数据库。

数据库使用 SQLite WAL、FULL 同步和事务；写入、检索、压缩由独立 isolate 顺序处理。应用关闭前等待工作流和配置保存完成，失败时阻止正常退出。强杀进程仍可能丢失尚未提交的变化。

工作流保存卡片身份、角色、上级、额外连接、画布位置、选中项及各智能体会话。会话包含正文、附件、工具参数和结果、用时步骤、重试及错误、模型上下文和压缩摘要。恢复时将未完成工具调用补记为取消，不恢复活动进程、待批准或待回答状态，不自动执行。

会话按智能体分别保存；未变化会话复用已有快照。较长字符串按 SHA-256 去重并以 Zstd 压缩，避免重复存放大段工具输出。记忆按独立事实存放，包含作用域、来源、内容哈希、lineage、修订号和基准哈希。检索采用 FTS5 trigram，短词使用子串匹配；中文长词拆分三字片段。当前没有向量语义检索。

复制卡片会复制聊天、上下文摘要、记忆开关、压缩阈值和当前长期记忆，创建独立 ID；两边后续编辑互不影响。复制、粘贴和创建副本只操作本地数据，不要求配置模型。导入包未绑定模型或原模型已不可用时仍可复制，副本保留待选模型状态，不自动套用其他智能体的模型；实际开始运行时再检查模型配置。

## 上下文与记忆步骤

默认启用记忆。请求前仅检索当前智能体的记忆，将最多 8 条相关记录作为参考注入；记忆不能授予权限，当前用户要求优先。模型可用 search_memory、save_memory、delete_memory 管理自身记忆；不应保存密钥或临时状态。操作显示在对应回复的“用时”内部。

默认上下文预算为 272,000 tokens，默认在预算的 90%（244,800 tokens）触发压缩，可在存储页分别调整。该默认值参考本地 Codex 模型目录中的 272,000 窗口档和源码中的 90% 自动压缩规则，是应用整理预算，不代表所有 GPT 模型或其他服务端模型都具有相同容量。已有有效的自定义预算和比例继续保留；新建智能体及缺失或无效的保存值使用默认值。估算按 ASCII 约四字符一 token、其他字符约一字符一 token，不能替代服务商精确计数。

应用使用当前模型生成摘要，可自动触发或手动执行。通常按用户消息边界划分；同一轮输出再次填满上下文时，保留本轮用户原文、近期完整的工具调用与结果，以及可容纳的最后一段助手正文原文。较早的进度合入摘要，不拆开工具调用和结果。流式正文和思考计入本地估算。跨过阈值后，应用结束当前模型请求，保留已显示的输出，在时间线上单独记录压缩，并用新请求从已输出的位置继续同一轮，不追加新的用户消息。成功后可以再次压缩；只有确实减少上下文才接受摘要，无有效压缩时不会把中断的输出标为完成。取消、失败或无可压缩历史时保留已有正文和上下文。助手可以用 `search_chat_history` 查找原始可见消息，再用 `read_chat_history` 按消息 ID 分页读取；历史是参考资料，不是当前指令或授权，也不包含推理、工具输出或附件。摘要不是无损替代，原始聊天、附件与用时记录均保留。

输入框下方显示流式输出速度、缓存命中和上下文已用。速度在回复完成时更新：只统计服务端上报了输出 token、客户端收到至少三批输出且首末批之间至少间隔一秒的模型请求，用这些请求的总输出 token 除以累计采样时长。它是客户端估算，不包含首包等待、实际工具执行或压缩耗时，也不代表服务端生成速度。缺少有效采样显示 `—`。缓存命中按服务端上报的缓存输入量除以总输入量计算。上下文已用按本地预算估算，明细中的绿色代表对话历史，蓝色代表压缩摘要，与分段条对应。左键点击缓存或上下文指标可查看明细。压缩期间，上下文指标原位显示转圈动效和“正在压缩上下文…”，悬停提示“右键可取消压缩”。右键菜单第一项为“管理聊天记录与上下文”，打开与智能体卡片相同的窗口，并选中当前智能体；下方可开始或取消压缩，选择任一项后菜单立即收起。操作结束后恢复显示占用百分比。

查询“我最早说的是什么”时，`search_chat_history` 可省略关键词，传入 `order: oldest`、`role: user` 和所需条数。记录中的智能体来信单独归类为 `agent`。在用时详情中，搜索会显示返回的匹配条数，按 ID 读取会显示所读消息的 ID 或未找到的结果。

## 单文件导入导出

| 类型 | 内容 |
| --- | --- |
| 记忆包 | 选定范围的当前长期记忆，可导入另一个智能体 |
| 聊天记录与上下文包 | 单个智能体的聊天、附件、用时、上下文、模型及审批设置，以及已绑定的角色卡 |
| 智能体包 | 聊天记录与上下文包的内容，加上该智能体的长期记忆，可选择包含下级分支 |
| 工作流包 | 所选范围内的完整智能体数据、连接和画布位置 |

全部导出为一个 .7z 文件，使用版本化 LilygoBox.agent-data 格式。外层 7z 存储 manifest.json 和 data.lzma2；正文为原生 LZMA2 高压缩数据，manifest 保存类型、原始长度及 SHA-256。不是通用软件直接浏览正文的普通 7z 文档包。LZMA2 使用 7-Zip 官方 SDK，运行时 Zstd 使用官方源码，两者通过 Dart code assets 构建。

导出在后台 isolate 编码、压缩和自校验，先写同目录 .partial 临时文件再替换目标。导入验证容器结构、格式版本、类型、长度和校验值，不向磁盘解压任意路径。哈希用于完整性检测和去重，不提供加密，也不能保证文件永不损坏。包内可含私密正文和附件，应自行保管；不包含模型服务 API 密钥，服务配置仍使用独立配置文件导入导出。

聊天记录与上下文、智能体和工作流包只收录导出范围内已绑定的角色卡。共享的 SillyTavern PNG／JSON 卡片数据只保存一次，各节点分别保存自己的扮演配置、启用状态和开场记录。导入时，相关角色卡与智能体一同写入数据库，卡库按内容复用已有卡片。长期记忆包只保存记忆。

当前实现按完整数据包在内存中解码，单次解码上限 512 MiB；不是无限大小流式归档。运行时也会载入完整会话，数据库持久化不等于无限聊天内存容量。LZMA2 高压缩偏重压缩率，速度取决于正文和机器，不承诺全球最高压缩率或最快速度。

## 导入冲突与原子提交

检查离散记忆内容哈希和 lineage。同一目标下相同内容跳过；内容分歧可查看现有内容与导入内容，选择跳过、同时保留或替换。导入检查中不编辑正文。替换使用 expectedHash 检查，防止覆盖预览后发生的新编辑。同包重复或同 lineage 分歧也需要审查。

导入聊天记录与上下文包、智能体包和工作流包会创建新 ID，重映射上级、连接、画布及记忆归属；不覆盖现有卡片，也不自动运行。这三类包均保留审批模式、自定义开关与目录规则、历史审批记录，以及聊天、自动审批和压缩模型及各自的思考强度。上下文预算、自动压缩阈值和压缩摘要也一并保存。不导出单次授权或 API 密钥。没有单独选择的审批或压缩模型继续跟随聊天模型。导入后使用本机配置的服务和密钥，专用模型不可用时不悄悄切换到其他模型。没有权限配置的旧包默认使用人工审批。智能体运行时禁止导入。先验证完整图和当前记忆，后在一次数据库事务内提交；验证或写入失败回滚，不留下半个工作流。

## 验证重点

回归测试覆盖重启恢复、大正文存储、会话附件与用时编码、压缩包损坏、重复和分歧、仅创建当前记忆表、导入失败回滚、复制记忆独立性、上下文压缩，以及浅深主题和 1.5 倍文字缩放。


## 存储页面样式

存储首页参考桌面存储管理界面，内容区限制为 760px 并在宽窗口居中。顶部显示此设备数据库占用、分类比例条、图例、数据文件路径及刷新入口；下方用紧凑管理行组织长期记忆、回收站、备份和清理。长期记忆与数据备份通过“管理”进入各自独立的标准 AppDialog 弹窗，不在首页折叠展开。弹窗按窗口高度限制内容区并内部滚动，关闭操作固定在底部；记忆列表仅显示两行预览，点击后在单独编辑窗口查看和修改完整正文。导入与导出窗口分为两个操作模式。导出模式按对象逐步展开：初始仅选择“智能体”或“智能体工作流”，未选择时不展示具体智能体和内容选项，导出操作禁用。选择智能体后，先指定智能体，再选择完整数据包、聊天记录与上下文包或长期记忆包；完整智能体数据可勾选包含下级。选择智能体工作流后导出当前工作流的完整数据，不包含回收站中的智能体。导入模式自动识别数据包类型并继续必要的记忆审查，记忆包需指定导入到某个智能体。范围选项以完整 ID 和名称区分，下方仅显示完整 ID 和名称；记忆归属不展示模型服务信息。智能体右键菜单的“管理记忆”使用记忆管理弹窗；导入、导出快捷操作直接打开系统文件选择器，不再打开通用“导入与导出”管理弹窗。范围与压缩阈值仍使用 SettingSelect；搜索和记忆编辑复用 SettingControlledTextField，支持回车搜索；操作按钮沿用 AppActionButton。

分类条使用真实数据库分配页总量作为分母：分别统计压缩正文／附件对象、会话／工作流状态、当前记忆正文的存储字节长度，剩余归入索引与预留空间。它是数据库内容构成，不是磁盘剩余容量或软件额度，也不是按表精确分配的物理空间；不扫描解压聊天正文。当前总量不包含临时 WAL／SHM 文件。占用统计是只读快照：没有写入时，重新进入设置或关闭管理弹窗复用上次结果，不重复扫描。数据库写入、清理或后台回收对象／整理数据库后，下次查看重新统计。手动刷新先保存工作流，再强制重算。统计及清理都在存储 isolate 中完成。

长期记忆列表读取不锁定管理弹窗：可关闭、搜索、切换智能体，已有有效归属时也可直接添加。切换归属或重新搜索后，只接受最新查询的结果，过期分页和错误都不得覆盖新列表。保存时核对打开编辑器时的智能体，提交期间防止重复操作；没有可用智能体时不能添加。浅深主题、1.5 倍文字缩放、长正文编辑及异步查询乱序均需回归。


## 回收站

从工作流或智能体工具删除智能体时，先停止运行并将每个被删除的智能体移入回收站。保存原 ID、名称、任务内容、模型配置、完整聊天、附件、用时步骤、模型历史及上下文摘要，同时保留当前长期记忆。回收站保存静态快照，不在后台继续运行智能体。主智能体删除后的分支提升规则保持不变。

设置 → 智能体 → 存储提供独立“回收站”管理行，可按名称或完整 ID 搜索智能体、还原、永久删除及清空；回收站内不编辑智能体，条目操作按“还原、永久删除”从左到右排列，永久删除使用公共红色危险操作样式。还原使用原 ID，不自动运行；原上级仍存在时恢复上下级，否则作为主智能体恢复。还原能够找到的额外连接及画布位置，不覆盖其他智能体后来调整的归属。权限重新授权，API 密钥不存入回收站。

长期记忆与回收站列表的卡片边缘对齐上方控件，右侧按钮留在滚动条内侧。长期记忆卡片在正文上方以小号辅助文字显示完整 ID，右键可“复制记忆 ID”；编辑已有记忆时，正文输入框上方的 ID 可选中，复制时不包含标签。记忆 ID 与数据目录路径统一使用应用的文本右键菜单，支持“全选”和“复制”。新建时不显示 ID。管理页和 `search_memory` 都支持用完整 ID 精确查找当前智能体的记忆。修正或合并时可用 ID 指明保留及修改的条目；只有用户明确要求删除的条目才调用删除工具，不跨智能体操作，也不把多次工具调用视为一次事务。

默认保留 30 天，可改为 7 天、90 天或不自动删除。软件运行时每分钟检查，退出期间到期的数据在下次启动时清理。缩短保留时间会清理到期数据时先弹出确认。永久删除和清空均需要确认；永久删除在同一数据库事务中移除回收站快照、长期记忆和搜索索引，并安排后台回收无引用正文对象。残留正文对象在后台合并回收；数据库文件在空闲且可回收空间达到整理条件时自动收紧，也可通过存储页“立即清理”执行。还原、编辑和永久删除会使旧画布撤销记录失效，避免撤销覆盖还原或复活已永久删除的数据；普通画布删除仍可撤销和重做。

普通工作流包与单个智能体包均不包含回收站内容。导入为包内智能体重新分配 ID，并重映射长期记忆、上级和连接，避免覆盖当前数据。

单个智能体导出完整数据包时，仅在当前智能体存在正常使用中的下级智能体时显示“同时包含下级智能体”；没有下级或下级已全部进入回收站时隐藏。切换智能体或导出内容会清除该勾选状态，实际导出前再次检查下级是否存在。

## 导出文件命名

智能体数据包的默认文件名统一使用全小写 `lilygobox` 前缀及本地日期时间 `YYYYMMDDHHmm`：完整智能体包为 `lilygobox-agent-完整ID-full-package-日期.7z`，聊天记录与附件包为 `lilygobox-agent-完整ID-chat-package-日期.7z`，记忆包为 `lilygobox-agent-完整ID-memory-package-日期.7z`，整个工作流包为 `lilygobox-agent-workflow-package-日期.7z`；勾选包含下级的工作流包为 `lilygobox-agent-workflow-package-日期.7z`（两种工作流包使用相同命名，不加入起点 ID，也不使用 branch/full 区分范围；包含下级的包内仍使用 agent 类型，导入时选择智能体）。单个智能体包保留完整 ID，不使用智能体显示名称；对象类型与包内容明确区分。通用配置与模型服务配置 JSON 沿用各自的日期后缀，保存窗口允许用户修改文件名。


## 搜索框样式

搜索入口统一使用紧凑的胶囊形输入框：浅灰或当前表面色背景、约 999px 圆角、左侧搜索图标、单行提示文字和右侧清除按钮（有内容时显示）。搜索框不使用外置说明文字替代占位提示；在存储、回收站和模型选择等列表中保持同一结构，避免搜索控件占用过多高度。


存储首页管理行顺序为长期记忆、聊天记录与上下文、导入与导出、无引用数据清理、回收站；回收站固定放在最后。回收站中的归档智能体内容只能查看、还原或永久删除，不提供名称、任务或记忆正文编辑。长期记忆弹窗不重复显示智能体名称和 ID 说明，也不在长期记忆列表中提供重复的数据导出入口；导出统一从“导入与导出”进入。


存储概览按实际保存内容细分项目，每项显示实际字节数；面向用户合并聊天记录与上下文，底层继续分别保存与统计。


存储概览分为六项：聊天记录与上下文、工作流、角色卡、回收站、长期记忆、索引与数据库空间。聊天记录与上下文汇总压缩正文／附件对象、聊天消息状态及上下文缓存／摘要字节；共享对象只计一次。角色卡统计卡库条目及其引用的头像、长文本和已留存的导入原件等压缩对象，从原分类中扣除；智能体绑定设定仍随所属会话或回收站快照统计。回收站单独统计已删除智能体快照、删除时间及连接等回收条目的已保存字节，从工作流占用中扣除；回收站引用且未归入角色卡的共享正文仍计入聊天记录与上下文，长期记忆仍计入记忆分类。记忆历史版本功能及其占用项已删除。所有状态项按保存后的 JSON 字节分拆，不解压全文，其他数据库页统一归入索引与数据库空间。回收站占用条与图例圆点使用粉色 `#ef748e`，与其他分类保持明确区分。


存储相关管理、导入导出、回收站、记忆编辑及确认弹窗的外框最大宽度统一为 440px，窄窗口继续自适应收缩。所有确认说明都必须在该宽度内自然换行，不能让一行长文本把提示框撑满窗口；只有确实需要表格、选择器或多列内容的专用弹窗才可显式使用更宽约束。长期记忆弹窗按实际内容确定高度，只有内容超出可用高度时才滚动，不以固定高度撑出空白。长期记忆归属及记忆导入目标只列出当前活动智能体，不包含回收站或失去归属的归档范围；记忆管理中没有可用智能体时禁用新增；长期记忆包导入仍可选择新建智能体。已打开窗口中的智能体若被删除，数据层也拒绝继续修改其长期记忆。回收站为空时，清空按钮同时禁用交互并显示中性灰色，不能继续呈现危险操作红色。

存储管理弹窗保持紧凑：没有说明的字段不预留空说明行，标题到控件间距 8px；搜索记忆与添加记忆同排，搜索框自适应占满剩余宽度。自动使用长期记忆开关采用 44×28 的紧凑布局区域，放在主标题右侧且垂直居中，说明独占下一行。没有下方控件的开关字段不再保留额外控件间隙。回收站和导入冲突列表按内容收缩，仅超过可用高度时滚动，不以固定高度撑开空白。


## 手动上下文阈值与容量边界

上下文缓存管理显示当前聊天历史的本地 token 估算，上下文 token 预算支持正整数输入（默认 272,000），压缩触发百分比支持 1–100 的整数（默认 90%，对应默认阈值 244,800 tokens），回车或失焦保存，不再限制为六个预设值；持久化不额外截断为 1,048,576。它是应用的整理预算，不是模型真实容量，不代表服务端确认的 token 数。系统指令、工具定义、检索记忆和压缩摘要等额外成本目前未完整计入该展示估算，不能据此保证请求一定放得下。实际自动压缩阈值为 `max(1, token预算 × 百分比取整)`，界面显示计算后的 token 值。请求开始前和流式输出期间均使用同一阈值，当前输出在指标中实时计入；成功轮次结束后清除临时输出计数。现有普通文本摘要压缩仍要求足够的历史条目；不能误写为已完全复刻 Codex 的容量管理。

对照本地 Codex：`codex-rs/protocol/src/openai_models.rs` 将默认有效窗口设为模型窗口的 95%，自动压缩预算默认约为完整窗口的 90%，二者不连乘。`codex-rs/core/src/session/context_window.rs` 同时检查整理预算和完整活动上下文边界。该策略给系统提示、工具及模型输出留出余量，不应等到模型窗口 100% 用满再压缩；窗口大小不明确的服务商不硬编码猜测模型容量。

OpenAI 官方 [Compaction](https://developers.openai.com/api/docs/guides/compaction) 明确独立 `/responses/compact` 请求的输入仍需处于模型窗口内。`context_management.compact_threshold` 的服务端压缩是另一种机制，不能直接套用到所有 Chat/Responses 兼容供应商。本应用当前是普通模型文本摘要，不应宣称使用加密 compaction item 或服务端原生压缩。

压缩百分比按智能体独立保存，复制、重启、导入导出均保留。允许 100% 但达到 95% 及以上时提示预留空间风险，不将输入预算宣称为已验证的模型容量。


### 导入对象与回收站导出边界

导入与导出分别选择“智能体”或“智能体工作流”，默认工作流。导入前读取并校验实际包类型：workflow 对应工作流；agent、chat、memory 对应智能体。类型与选择不匹配时提示并终止，不进行写入。只有智能体导入显示记忆包的目标归属；工作流不显示无关的单智能体归属。

所有导出只包含活动智能体。工作流包排除 recycleBin、回收站智能体的聊天正文、附件和记忆；单智能体、聊天和记忆导出拒绝回收站中的归属。移除包含回收站的选项和 backup 包类型，不保留旧类型兼容。本地回收站数据仍按原有还原及清理规则保留。

存储概览仅显示带用途标签的智能体数据目录（数据库文件所在文件夹，不展示 main.db 文件路径），说明其保存聊天、上下文、记忆、正文及附件。显示运行时实际使用的路径，不将数据库中的逻辑分类虚构为独立目录；下载缓存不属于智能体存储主题，不在此页面展示，也不计入智能体数据库占用条。

## 自动整理与立即操作结果

存储后台在初始化和写入后合并安排维护，默认等待 10 秒无存储请求；持续请求时最多延后 5 分钟处理残留对象，两次后台维护至少间隔 1 分钟。工作在数据库 isolate 中执行，保留所有仍被聊天、工作流和回收站引用的正文对象，不删除当前记忆。日志使用不等待其他连接的 PASSIVE 检查点；完整数据库整理只在空闲、空闲页不少于 8 MiB、占数据库页数至少 20%，且同一后台实例距上次完整整理至少 30 分钟时执行，避免每条流式消息都重写数据库。关闭时取消维护定时器；后台维护失败只记录并稍后重试，不把已完成的保存变成失败。

存储页“清理存储空间”与“回收站”共用最后一张卡片，纵向排列，回收站在最后；“导入与导出”使用独立卡片。手动入口只说明立即操作的用途，按钮名为“立即清理”，不在手动说明中混入后台机制。点击后在底部显示实际删除的残留对象数量及数据库和 WAL 文件前后实测释放空间；只有文件空间减少时显示整理结果，两者均为零时显示“暂无需要清理的数据”。后台自动维护不弹出通知。

“立即压缩”结束后在底部显示明确结果：成功时显示聊天历史 token 估算的前后值，估算不等同于完整请求容量；历史不足、未配置可用模型、取消或未产生有效摘要分别提示，不将未执行视为压缩成功。失败时显示失败提示，原有聊天正文和附件的保留规则不变。

智能体运行时，自动和手动压缩都归入当前回复的「用时」。展开压缩行可查看实际模型、可用的思考强度、阶段、压缩耗时及结果；成功时显示压缩前后的估算 token 数。回复总用时已包含压缩。空闲时手动压缩沿用独立记录，旧记录也保留原样。流式输出中压缩会先保留已显示的正文并暂停旧请求，压缩成功后发出续写请求，正文不因压缩而拆成两条。压缩失败时保留现有正文，不自动发送后续正文请求或排队消息。

聊天上下文阈值用来决定何时压缩，不直接作为摘要请求的输出上限。滚动摘要提示模型合并旧摘要、压短重复内容，并给出按批次估算的正文长度目标。使用思考模式的 DeepSeek Chat Completions 压缩请求按实际输入批次（含滚动摘要）为思考和摘要合计分配 2,048–4,096 个输出 token，不使用「聊天预算减触发阈值」作为上限。若服务报告输出截断，同一次压缩最多扩大额度重试一次（至多 8,192 token）；沿用原模型、思考强度和同一批输入，截断的部分不作为下一次输入。「用时」记录重试和最终结果。各服务实际支持的限额以接口为准。

压缩失败时，正文区直接显示红色失败原因，不必先展开。展开「用时」中的红色「上下文压缩失败」行，可像工具调用一样查看和复制错误详情。模型只返回思考、空摘要、调用工具、内容被过滤或报告输出达到上限时，明确显示对应原因；服务拒绝请求时保留原始报错和可用的 HTTP 状态、服务错误码。若接口提供结束原因或输出 token 用量，也一并显示。消息的复制按钮复制正文和正文区的红字，两者都为空时才禁用；「用时」错误详情仍单独复制。不接受达到上限而截断的摘要。有效摘要未减少估算用量时，手动压缩只显示「上下文未改变」，自动压缩则标为失败；两者都不显示「已完成」，也不改动原上下文或切换服务。旧记录未保存的原因无法追溯。

自动压缩进行中停止本轮，再点“继续生成”时，应用用新请求接续原压缩记录，不插入另一条，不计停止期间的等待时间。压缩成功后才请求剩余正文；若正文在压缩前已结束，则只完成压缩，不再请求正文。以后再次触发的独立压缩按触发顺序记录。

工具执行期间收到手动压缩请求时，等该批工具结束后再压缩。已结束的工具不会继续计时。同一轮内，查历史、重试或再次压缩不会清除续写指令；若压缩后的请求正文缺少原文断点，单独附上最后一小段已显示的原文，作为参考数据而非新的指令。

手动复测生成途中压缩：重新导入 `artifacts/lilygobox-auto-compaction-conversation-test.7z`，给导入的智能体选择聊天模型，并在本机指定 DeepSeek 压缩模型和想测试的思考强度。测试包内聊天预算为 12,000 token，阈值为 28%（3,360 token），预置历史约 2,600 token。发送短提示，例如「请连续输出 80 条编号的中文读书笔记，每条约 80 字，不要先给提纲，不要调用工具」。应先看到正文输出，再在该回复的「用时」中看到自动压缩；成功后不必再发送消息，正文会继续生成。若只在回复结束后看到压缩，换一条能持续流式输出的更长回复复测；实际触发时机取决于模型输出长度和流式分块。

如果发出正文请求前需要压缩，当前回复直接显示压缩阶段。此时停止会在同一条回复中保留取消记录；点击“继续生成”仍从该记录接续。

模型报告上下文超限时，应用也会尝试压缩恢复。一个尚未成功完成的模型步骤最多自动恢复一次；已执行的工具结果仍作为上下文，不重放已执行的调用。若恢复前已经输出正文，先固定其内容，再继续同一轮。压缩失败或无法缩短时显示失败，停止时保留已有输出，不自动消费排队消息。

纯思考仍计入实时占用，但不会单独触发流式请求的中断，避免还没有正文进度就反复重启同一步骤。手动继续后若模型在输出前报告超限，压缩重试仍保留已经显示的正文前缀。
删除入口的主标题统一为“聊天记录与上下文”，按钮简写为“删除”，确认窗口保留“删除聊天记录与上下文”标题，明确同时删除该智能体聊天历史和上下文摘要，保留长期记忆。弹窗内的结果通知仍使用公共底部 SnackBar，由内容区 Navigator 外的 Scaffold 承载，绘制在弹窗及遮罩上方，同时受窗口圆角裁剪。

## 导入导出交互与处理进度

导出保留智能体与智能体工作流的范围选择；智能体内容选项为完整数据包、聊天记录与上下文包、长期记忆包。聊天记录包含正文、图片、附件、思考和用时记录；聊天包同时保存模型上下文历史、压缩摘要及压缩设置。长期记忆包只保存当前长期记忆及其必要元数据。

导入先选择一个 `.7z` 数据包，通过包内清单自动识别类型，不要求预先选择智能体或工作流。选择文件后直接识别并继续导入，不显示“重新选择、包类型、文件名、再次导入”的中间步骤。设置中识别长期记忆包后打开独立紧凑目标选择窗口，提供已有活动智能体及“新建智能体”，不将目标控件嵌入导入导出管理页；确认目标后审查重复与冲突；其他包创建使用新 ID 的智能体及包内连接，不覆盖现有智能体。文件选择取消不写入数据。

确认文件或保存位置后显示独立、紧凑的进度弹窗，展示当前处理阶段和已用时间。压缩、解压、文件读取、写入及 SHA-256 完整性校验按实际处理字节显示当前阶段百分比；导入分析中已有总条数的阶段按实际处理条数显示。SHA-256 在后台 isolate 中以 256 KiB 分块处理，报告已校验字节，并在块间检查取消。容器结构检查、JSON 编解码、数据库原子提交等没有可测量进度的阶段保留不确定进度，切换阶段后清除前一阶段百分比，不将阶段百分比冒充全流程总进度。文件选择器打开期间不显示处理进度，也不将页面设为忙碌或改成灰色禁用样式；原生模态窗口负责阻止后台交互，另用不影响外观的内部标记防止重复打开。确认文件后才进入实际处理状态。

取消采用协作机制，压缩和解压在原生处理检查点停止并释放资源，导出临时文件清理后才结束；最终文件替换及数据库原子提交期间禁用取消。导入准备阶段取消不写入数据，正式提交使用事务，失败不留下半份数据。成功后关闭进度弹窗，通过公共底部通知分别提示导入完成或导出完成；取消和失败分别提示，不使用成功提示。


## 对话后自动整理长期记忆

长期记忆管理页将“自动使用长期记忆”与“自动整理长期记忆”分成两个开关，均按智能体保存，默认开启。前者在每轮对话前检索相关事实作为回答参考，并允许模型调用记忆搜索、保存和删除工具；它不是仅在智能体启动时检索一次。关闭它会停止自动检索及记忆工具使用，保留已有数据，并禁用依赖它的自动整理开关。自动整理的独立偏好仍保留，重新启用长期记忆后恢复。

自动整理在一轮正常对话及工具链结束后，用当前模型额外请求一次，筛选明确的长期偏好、项目约束、已确认决策和可复用事实，对照检索出的已有记忆避免语义重复。聊天原文、附件和上下文仍分别保存，不将全部聊天直接复制成记忆；问候、临时进度、推测及凭据等信息不应保存。模型可返回空列表，代表本轮没有新增的长期事实。

候选记忆按当前智能体归属在数据库事务中保存，标准化内容哈希再次去重，只新增，不自动覆盖或删除已有条目。来源记录对应回复 ID，保存会创建正常的检索条目，不保存历史版本。模型输出限制用于校验单次非可信响应，不限制智能体累计记忆数量。相关步骤出现在本轮“用时”中，展示实际新增和重复跳过数量。停止、失败、关闭开关或销毁智能体后不继续应用未完成的模型整理结果；整理请求失败不把已生成的正常回复改成失败，也不将整理 JSON 显示为聊天正文。

自动整理会额外消耗当前模型的 API 用量与处理时间，不能保证模型每次都完整、准确地选出全部长期信息。用户仍可手动检查、修改、删除及导入导出长期记忆。


回收站中的每个智能体以独立圆角卡片显示，复用 `surfaceContainerLow` 与弹窗的 `surfaceContainerHigh` 区分层级；未选中卡片不显示边框或底部分割线，内边距 12px、圆角 12px、卡片间距 12px。名称、完整 ID 和自动删除剩余时间保留在卡片内；剩余时间合并为一行，按天、小时或分钟显示，不自动删除时直接说明，操作按钮在右下角按“还原 → 永久删除”排列，窄窗口允许自然换行并保持右对齐，沿用紧凑按钮间距和红色危险操作规范。


## 卡片与画布快捷导入导出

卡片右键的“导入长期记忆包”直接选择文件，目标固定为该卡片对应的智能体，只接受长期记忆包；“导出长期记忆包”和“导出智能体包”直接选择保存位置，后者只导出当前智能体。包含下级的工作流导出仍可在设置的导出管理中选择。画布空白处右键提供“导入数据”，自动识别智能体、聊天记录与上下文、工作流及长期记忆包并创建新 ID。画布导入长期记忆包时新建一个独立主智能体并将记忆归属到它，不沿用当前选中的智能体，也不要求先有智能体；新智能体不自动运行，需用户选择模型。文件选择或记忆审查取消时不创建智能体，智能体与记忆在同一事务提交，失败不留下空卡片。

快捷导入直接选择文件并自动识别，不打开导入导出管理窗口，也不额外弹出包信息确认框；设置管理入口选择文件后直接继续处理，不再停留在包信息页要求再次点击导入。两种入口均保留实际处理进度、取消及记忆条目审查与冲突处理。文件选择取消时不打开额外管理窗口。失败通知必须包含有效的失败原因，不能仅显示“详情：”前缀；无效或损坏的数据包使用本地化说明，并提供紧凑的失败窗口以重新选择文件或取消。成功、取消和失败沿用公共底部通知。快捷导入导出沿用现有校验、事务和临时文件清理，不改变数据写入规则。

记忆条目审查采用紧凑卡片与独立的有界滚动列表，底部操作保持可达，不显示原始哈希值。新条目、重复条目和冲突条目分别标明状态，冲突可选择跳过、同时保留或替换；导入审查不提供正文编辑，只选择条目的导入方式；正文修改统一在导入后的长期记忆管理中完成。冲突处理选择使用草稿，只有确认导入才应用，取消不改变原始导入计划。全部条目跳过时仍允许继续导入包内的智能体和聊天记录。


长期记忆管理中的记忆卡片列表使用独立、有高度上限的滚动视口，搜索、添加和自动使用、自动整理开关均在列表外；记忆条目增多不再撑高整个弹窗。列表按内容收缩，最大高度随窗口自适应。卡片距弹窗两侧各 24px，滚动条放在卡片外侧且不覆盖按钮；内外滚动条保留各自的通道。特别矮的窗口或大文字下，外层仍允许滚动以保证固定设置可达。

回收站卡片列表拥有独立滚动区域，最大高度随窗口在 100–300 px 之间调整，可用高度不足时继续收缩，多个条目不继续撑大提示框；自动删除设置、搜索与关闭操作位于列表之外。回收站条目及长期记忆条目背景使用与存储主页长期记忆卡片相同的 `theme.primary`。智能体卡片右键的“导出聊天记录与上下文包”只导出该智能体的数据。


从画布快捷导入时，读取、校验和准备阶段通过弹窗显示进度并提供取消。进入最终写入阶段后，画布中央显示“正在完成导入”和不定进度条。

## 记忆与回收站的多选操作

卡片右键菜单提供“选定／取消选定”和“全选”。打开菜单不改变选区；选定或取消选定只影响当前卡片，全选与列表的 Ctrl/Cmd+A 一样，仅选择当前筛选结果中已加载的条目。长期记忆卡片右键还可复制完整记忆 ID。

长期记忆及回收站条目采用相同的桌面选择规则：单击选中一项，Ctrl（macOS 为 Command）单击增减选择，Shift 单击按当前显示顺序连续选择，Ctrl+Shift 单击追加一段范围。列表获得焦点后，Ctrl+A 选择当前筛选结果中已加载的条目，Esc 取消选择；切换智能体归属时清除选择，编辑、提交或清空搜索均保留已选条目，避免跨范围误操作。选中状态使用主题色 1px 细边框，沿用输入框的 167 毫秒 fastOutSlowIn 过渡，不显示勾选图标、不额外染色背景，长期记忆卡片无悬停底色和点击水波纹，并保留选中语义。点击卡片、搜索框和操作按钮之外的空白区域取消选择；点击搜索框或选择搜索文字保留卡片选择，实际更改搜索条件也保留已选条目，筛选暂时隐藏的已选条目仍计入批量操作；点击批量操作按钮不清空选择，确认框取消后仍保留选择。

长期记忆保留右侧编辑按钮，卡片单击只负责选择；选中后显示带数量的红色“删除所选”按钮。回收站选中后显示“还原所选”和右侧红色“永久删除所选”按钮，弹窗宽度保持不变；按钮固定在搜索栏右侧同行，采用紧凑间距与弹性宽度，空间紧张时缩放操作区域以避免溢出，标题栏“清空回收站”仍针对整个回收站。Delete 在列表焦点内触发批量删除确认，永久删除及记忆删除都必须确认；取消后保留选择与数据。输入框中的全选、删除和选区快捷键仍用于文字编辑，不能触发卡片操作。操作期间禁用重复提交。

回收站右上角的“全部还原”和“全部清空”覆盖搜索结果之外的卡片，确认时“全部还原”显示实际总数。单条还原和还原所选在点击后立即开始，“全部还原”在确认后开始。还原由工作区在后台准备并提交，不再打开进度与取消弹窗。回收站保留当前搜索条件，保存成功后原地更新列表，操作期间随时可手动关闭。切到智能体画布时，准备与保存阶段显示“正在还原智能体…”，不估算百分比；大量卡片保存成功后沿用画布的分帧加载和实测百分比。还原失败时保留原条目，可在回收站重试。批量还原优先恢复选中的上级，保留原智能体 ID、聊天、记忆和可恢复的连线，一次提交整批数据。

回收站常规布局仅让内部卡片列表滚动，筛选设置、搜索和关闭操作保持在列表之外，不能同时显示外层与内层两条滚动条。滚动视口延伸到弹窗边缘，卡片与搜索区域保持同样的 24px 留白，滑块位于卡片外侧。多个卡片不能撑大整个提示框；狭小窗口和大字号下仍需保证所有控件可达。

长期记忆管理按归属标题与说明、智能体选择、自动使用长期记忆、自动整理长期记忆、搜索与操作、记忆列表的顺序排列。归属说明应明确下方记忆与自动记忆设置仅对所选智能体生效。

此类胶囊搜索框的清除按钮统一复用 SearchClearButton，使用公共 MenuItemSurface 的 150 毫秒悬停渐变、圆形背景与点击反馈；设备管理、模型选择、长期记忆和回收站保持一致。

长期记忆管理卡片仅显示记忆正文和操作按钮，不显示来源消息 ID、自动整理来源 JSON 等内部元数据。本地生成记忆可在底层保留当前对话来源；导出时将来源替换为固定的 `{"imported":true}` 标记，不携带原消息 ID 或转移链。导入也独立执行同样的来源清洗，不信任包内旧来源；不提供旧来源格式的启动迁移或兼容读取分支。多次转移不会累积旧智能体及消息 ID，原始本地记忆的来源不受导出影响。记忆 ID、当前归属、内容哈希、lineage 和必要冲突元数据仍按原规则处理，不影响去重、编辑或删除。

画布多选智能体后右键，数据操作区仅显示“导出智能体工作流”，不显示管理记忆或单智能体的导入导出操作。工作流包只包含所选活动智能体及其内部连接、画布位置、聊天记录与上下文和当前长期记忆，不自动包含未选下级、不包含回收站；未选择上级的节点在包内作为主智能体。单选保留原有针对该智能体的管理、导入与导出入口。多选导出沿用工作流包类型和命名，导入时创建新 ID。

设置导入长期记忆时，“新建智能体”创建不自动运行、无模型配置的独立主智能体。目标选择与记忆审查期间不创建节点，确认后复用智能体包的原子导入，同时写入智能体及当前记忆。取消目标选择、取消记忆审查或提交失败均不留下空智能体；没有已有智能体时仍可选择新建。导入已有智能体时只写入其长期记忆，不创建额外节点。

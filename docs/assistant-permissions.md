# AI 工具权限与批准

## 入口与会话范围

主页输入框底部、附件按钮旁提供权限入口，显示当前的“请求批准”或“自定义权限”。使用现有 `MenuItemSurface`、`PopupMenuSurface` 和 `PopupMenuTransition`，复用主题、悬停和展开交互。内容可滚动，滚动条与边缘保持全局 6px 规则。

权限只在当前会话内保存；清空会话或重新启动应用后恢复“请求批准”。不会将一次工具批准隐式升级为文件夹授权。

## 权限划分

参考本地 Codex 中 `AskForApproval` 与 `SandboxPolicy` 分离的方式，将“操作范围”和“范围外如何处理”分开管理；本项目不实现 Codex 的命令沙箱，也不声称获得操作系统级隔离。

- **请求批准**：软件设置、当前时间、执行环境查询和公开 HTTPS 网页可直接使用；本地目录浏览、文件读取和文件写入逐次批准。每条本机命令只请求一次“运行本机命令”批准，不再按设备、固件或安装用途重复询问。
- **自定义权限**：保留“运行本机命令”“文件完全访问”“允许联网”三个开关。运行本机命令统一涵盖命令调用中的设备访问、固件烧录、工具安装和环境修改；不再为这些用途分别设置开关或重复批准。文件完全访问和允许联网分别控制内置文件工具和网页工具，不限制已获批进程的文件或网络行为，也不影响聊天所需的模型 API 连接。开关关闭表示使用相应工具前询问，而非系统级禁止。
- “默认文件夹访问权限”提供每次都请求批准、仅允许读取、允许读取和修改三个选项，仅决定之后新增文件夹的初始权限，修改默认值不会改变已添加文件夹。
- 每个文件夹在移除按钮左侧提供实心盾牌权限按钮，点击盾牌直接展开公共选项菜单，单独设置该文件夹及其子文件夹的访问权限，不先显示一行下拉控件，立即生效。父子文件夹分别授权时以路径最具体的设置为准，子文件夹的限制不会被父文件夹的授权覆盖；移除文件夹会同时移除该项权限。未授权范围仍请求批准。
- 超出自动授权范围的操作一律逐次请求批准，不提供关闭此行为的开关。
- **文件完全访问**：开启后，内置文件工具无需逐文件夹授权，并隐藏默认文件夹访问权限、添加文件夹及已添加列表。隐藏不删除原有配置；关闭后恢复。完全访问仍受系统账户权限和内置工具的格式、大小、路径、元数据保护规则限制。

## 工具与执行边界

工具定义向模型公开，但每次执行由软件校验，不以模型的自然语言承诺代替检查：

| 工具 | 功能 |
| --- | --- |
| `get_current_time` | 返回本机日期、时间、时区及 UTC 偏移 |
| `read_webpage` | 读取指定公开 HTTPS 地址的文本内容 |
| `list_directory` | 列出目录的直接子项，最多 200 项 |
| `read_file` | 读取 UTF-8 文本文件，最多 1 MiB |
| `write_file` | 创建或更新 UTF-8 文本文件，最多 1 MiB |
| `get_execution_environment` | 查询操作系统、默认 shell 和工作目录，不返回整份环境变量 |
| `run_command` | 启动本机程序，显式传递可执行文件、参数列表、工作目录和操作目的 |
| `read_process` | 按输出游标读取已批准进程的日志和退出状态 |
| `write_process_input` | 向已批准进程发送标准输入 |
| `stop_process` | 停止已批准进程，在 Windows 上同时请求终止子进程 |

网页读取限制为 HTTPS 默认端口，禁止凭证 URL、私网/本机及保留地址和系统代理。最多跟随 5 次 301、302、303、307、308 跳转；逐跳重新验证协议、端口和全部解析结果，固定到已验证的公网 IPv4 地址，禁止降级 HTTP，并检测循环。每跳使用独立客户端，不跨源携带 Cookie 或授权信息；整个跳转链共享 30 秒总时限。DNS 地址校验后固定连接到该地址，并显式完成 TLS 握手，使用原始域名进行 SNI 和证书验证（自定义 `HttpClient.connectionFactory` 不会自动为直连补上 TLS）；取消请求时同时终止 TCP 连接和 TLS 握手；支持公网 IPv4，响应限时、限大小，停止生成时关闭连接。网页内容作为不可信数据返回，不能据此扩大权限。返回实际最终 URL 和原始请求 URL；接收 text/* 或 application/json，按声明的受支持编码解码，默认 UTF-8，解码失败不使用乱码替代。正文超过 1 MiB（解压后）或为空时明确失败，不静默截断。工具不执行 JavaScript，不继承浏览器登录态；返回 HTML 仅表示取得静态源内容，不保证取得动态正文。暂未接入通用搜索服务，不把网页读取标记为互联网搜索。

文件路径必须为绝对路径。自动授权同时比较路径范围和解析链接后的实际目标，防止通过符号链接或 junction 越界；批准后再次验证目标。Windows 拒绝 UNC、设备名及备用数据流。仓库与应用敏感元数据目录（`.git`、`.codex`、`.agents`、`.aws`、`.ssh`）禁止写入。

覆盖已有文件要求 `expected_content` 与现有内容完全相同；内容已变化时要求重新读取。写入通过同目录临时文件替换，避免原地覆盖硬链接目标。内置文件工具不创建缺失父目录，也不提供删除接口；通用命令经过完整授权后可调用本机程序执行这些操作，不能把内置文件工具限制当作命令沙箱。

这些属于应用工具层检查，不能防御本机其他进程在极短时间内恶意替换路径的全部竞争条件，不应作为不可信本机程序的系统安全边界。

## 逐次批准

批准区域仅操作按钮遵循[标准提示框与操作按钮](dialog-style.md)：按钮使用 12px 文字和公共按钮尺寸，浅色普通按钮采用“添加文件夹”的 6% 混色。面板保留原有双层背景、22px / 17px 圆角、5px 层间距与 16px 内容留白；标题保持 15px、w600，操作名称 14px、w500，路径 13px。不得因统一按钮而改变面板背景、文字或布局。面板保留在输入区，内容内部滚动，拒绝与允许一次固定在底部。

- 需要批准时，底部输入区整体切换为批准面板，临时隐藏文字输入、附件、队列与模型控制；批准或拒绝后恢复，保留草稿、附件与队列，不自动抢回输入焦点。双向切换复用 `PopupMenuPageTransition` 的 150ms 线性淡入淡出，遵循[公共页面切换动画](page-transitions.md)，不额外添加位移或缩放。
- 面板展示操作和请求路径；解析后的实际路径不同时额外展示，避免重复。长内容在面板内滚动，操作按钮固定可见。
- 待批准请求独立于聊天消息保存，不在聊天记录中插入批准卡片；操作结果继续保存在对应用时详情中。
- 写入额外展示修改前、修改后的完整文本，供用户核对。
- “需要批准”标题左侧使用填充的 `Symbols.shield_rounded`（`fill: 1`）。使用“允许一次”和“拒绝”，等待期间状态为“等待批准”。
- 批准只对应固化后的当前调用参数；后续同类调用重新检查。
- 拒绝时将失败结果返回模型；停止生成、引导打断或销毁 provider 时取消待批准请求，禁止继续执行。
- 已批准与实际执行成功分别记录，不能把批准状态写成操作成功。

读取到的文件内容和命令输出可能发送给当前配置的模型服务，权限页面明确说明。所有静态界面文案同步维护中英文 ARB 和生成产物。

## 回归验证

权限边界、逐次批准、拒绝、停止取消、重复点击、自定义目录自动授权、清空会话重置，以及中英文与深浅主题下的权限界面均有独立测试。模型请求使用模拟响应，文件操作使用隔离临时目录。

## 权限入口交互

输入区“请求批准 / 自定义权限”入口使用与模型选择一致的锚定展开菜单，复用共享浮层背景、阴影与展开淡入动画，不使用居中对话框和遮罩。主菜单以“图标 + 模式名称 + 简短说明 + 当前勾选”排列。点击“请求批准”立即切换并收起；点击“自定义权限”立即切换并进入同一浮层内的配置页。配置修改立即生效，无“应用 / 保存 / 取消”按钮，点击外部只关闭菜单，不撤销修改。返回箭头回到模式列表。

文件访问等级复用公共 `SettingSelect`。菜单内使用独立下拉浮层时，必须把外层 `MenuController` 作为 `dropdownTapRegionGroupId` 传给公共下拉框，下拉面板通过同组 `TapRegion` 参与点击判定；只给实际下拉面板分组，不把全屏关闭区域算入菜单内部。这样选择选项只收起下拉框，不关闭权限面板；点击外部仍可关闭。回归测试模拟真实点击，不直接调用回调。


### 菜单视觉规范

- 权限面板直接对齐选择模型菜单的文字与交互规格，不混用 Material 默认 `bodyMedium`、`labelSmall` 字号。标题 13px、`w600`，字段标题 12px，说明 11px（行高 1.4），控件值 13px；继承应用字体并保留系统文字缩放，不固定裁切文字。
- 基础内容宽度 320 逻辑像素，随文字缩放增加，并受窗口可用宽度限制。面板配色复用模型选择的 `PopupMenuSurface`。模式条目默认与面板同色；选中底色使用主题选择色，悬停使用主题主色，文字和图标随状态切换为对应高对比前景色，勾选使用普通前景色。公共下拉框按面板背景计算底色，不新增主题颜色。
- 字段标题、说明、控件外沿在同一左边线。字段分组间距 16px；有说明时按“标题 → 4px → 说明 → 8px → 控件”排列，无说明时标签到控件 8px；模式名称与说明间距 4px。模式条目使用 6px 圆角、左右内边距 10px、上下 6px，高度按实际换行内容增长。
- 模式项的勾选和图标跟随控件前景色，不单独染色；选中和悬停的底色、前景色与模型列表一致。
- 自定义配置页只有左上角独立返回按钮（26×26，图标 16px）可返回，标题与整行留白不响应返回。文件夹移除按钮与返回按钮使用相同的浮层表面底色，以及基于该表面计算的悬停和按下反馈。各能力类别使用右侧紧凑 `Switch`（布局区域 44×28），启用色取主题紫色，开启和关闭均显式保留白色滑块。标签与开关垂直居中。文件访问使用公共下拉框；“授权文件夹”标题与带 `add` 图标的添加按钮同排，标题在左、按钮在右并垂直居中；说明在下一行占满可用宽度，与模型服务的读取模型列表布局一致，说明与文件列表之间保留间距。添加按钮采用菜单表面向文字色混合 6% 的浅色底，内边距左右 8px、上下 7px，保留共享按钮的悬停渐变和波纹。所有配置修改立即生效，范围外操作默认请求批准。

- 权限列表与自定义权限页之间使用公共 `PopupMenuPageTransition` 渐变淡入淡出，与选择模型列表和思考强度页保持一致；遵循系统减少动画设置，退出页不响应输入。

授权文件夹列表最高 144px（默认字号约 6 行），少量条目按内容收缩，超出后在列表内部独立滚动。使用公共滚动行为与自动显隐的滚动条，滑块按全局 6px 靠边规则定位，内容预留 20px 避免移除按钮被遮挡；文件夹标题、添加按钮和会话说明不随该列表滚动。

添加文件夹使用 Flutter `file_selector` 的标准 `getDirectoryPaths()` 多选目录流程，可一次添加多个目录。原生对话框中的复选框显示遵循系统行为，不额外注入 Shell 复选框标志、定时重试或自定义原生通道；取消不修改授权，批量添加保留选择顺序并过滤重复项，Windows 路径按不区分大小写及斜杠方向比较。

自定义批准页及权限条目的主标题、次标题统一遵守[全局输入框样式的文字规范](text-input-style.md#主标题与次标题文字规范)，以“编辑服务”的字段标题和说明为基准：主标题 12px、主题 textColorSecondary；次标题 11px、1.4 行高、主题 textColorTertiary，均不额外加粗并继承应用字体与文字缩放。字段标题到说明保持 4px。该规则涵盖网页访问、默认文件夹访问权限和授权文件夹等字段；菜单页标题与控件值保留各自的组件规格。

### 网页错误与回归验证

网页失败以 `ok: false`、稳定的 `error_code` 和可用时的 `status_code` 返回模型，同时在用时详情显示当前语言的原因和恢复建议。区分地址策略、DNS、连接、TLS、超时、HTTP 状态、无效/循环/过多跳转、内容类型、编码、空内容、大小限制及取消；不把 HTTP 403 直接归因为反爬。含凭据的 URL 在准备阶段拒绝，错误结果不回显凭据。

本地 HTTPS 回归覆盖正常读取、五种跳转状态、逐跳 DNS 重检、私网和混合解析结果、HTTP 降级、循环和跳数上限、Cookie 隔离、HTTP 错误分类、编码、大小、空内容、TLS、DNS、超时及取消；模型工具回归验证结构化失败与详情记录。测试通过隔离连接映射访问本地服务，不放宽生产地址校验。

文件访问等级统一使用实心盾牌：绿色表示每次请求批准，黄色表示仅允许读取，红色表示允许读取和修改；默认权限下拉框、文件夹独立权限下拉框和文件夹权限按钮保持相同颜色映射。文件夹列表仅展示文件夹名称，悬停显示完整路径；权限按钮悬停提示仅显示当前权限名称，不添加“文件夹权限”前缀。默认权限下方以小字说明其用途是新添加文件夹的初始权限。

文件夹盾牌入口复用公共 `SettingSelect` 的自定义触发按钮，直接打开同样的等级选项菜单，保留选中勾、等级颜色和公共渐变动画。独立选项菜单与外层权限菜单共享点击区域，选定等级只关闭选项菜单；菜单宽度独立于盾牌尺寸，靠近窗口边缘时向内避让、下方空间不足时向上展开。

“默认文件夹访问权限”的说明紧跟主标题，标题与说明之间为 4px，说明下方留 8px 后显示权限选择控件；禁止把说明放在下拉框下方，使其与主标题分离。

## 本机工具与设备工作流

不绑定或预装特定烧录程序。AI 先查询执行环境，再根据项目和设备选择本机工具；缺失工具可以在获批后自行从官方来源下载、安装和调用。调用方必须提供绝对且存在的工作目录、可执行文件、字符串参数列表和简短目的；不拼接隐式 shell，执行脚本时由模型显式指定 PowerShell 等程序。

当前没有操作系统级命令沙箱。任意程序都可能间接访问文件、联网、连接设备、写固件或安装软件，因此本机命令统一通过“运行本机命令”授权，不依赖模型自报用途分类。请求批准模式下每条命令请求一次；自定义权限开启该开关后，普通命令可直接执行，命中危险检查或 prompt 规则时仍请求一次批准，命中 forbidden 规则直接拒绝。文件完全访问和网页开关不参与命令的重复批准。批准面板显示目的、程序、参数、实际工作目录及未隔离说明；拒绝或停止后不启动进程。单次批准仅放行本次固化命令及其子进程，不修改开关，也不授权后续命令。

命令开关是启动前的批准门禁，不能撤销已启动进程的系统权限，也不能限制它的实际文件、网络或设备行为。范围更细的独立限制必须先引入真正的系统沙箱。

进程会话仅在当前 provider 中有效：模型可通过返回的 process_id 轮询日志、写入标准输入和停止进程，无需重复批准同一进程的日志读取。模型应持续检查 running、exit_code、timed_out 和 stopped，不能把成功启动当作执行成功。命令输出上限 65536 个字符，超出保留尾部并标记 output_truncated；output_cursor 用于读取后续增量。默认执行时限 600 秒，可显式设置为 1–3600 秒；最多同时运行 8 个进程，最多保留约 32 个会话结果。

停止生成、引导打断、清空会话和销毁 provider 会取消待启动命令并终止运行进程；超时自动终止。Windows 使用独立参数调用 taskkill /T /F 请求结束进程树，不授予管理员权限。模型不得分离后台进程，设备连接应留在受管理进程中。ESP32 工作流需先识别目标设备和固件布局，按实际工具日志判断构建、烧录及启动结果；不预设某个烧录工具，也不凭空猜测写入偏移。

新增回归覆盖：命令仅请求一次批准、拒绝后不启动、命令开关独立授权且不重复询问文件和网络权限、完整文件授权、隐藏配置恢复、真实进程日志和非零退出、标准输入、日志截断、超时、启动期间取消和运行期间取消。测试只执行隔离的本机测试命令，不下载工具、安装驱动或烧录实际设备。

## 命令执行前保护

本机命令在原有能力授权之外，增加执行层危险操作确认和 `allow / prompt / forbidden` 规则。开启全部自定义权限也不跳过危险操作确认，禁止规则不能通过批准放行。本次不新增系统提示词约束。配置位置、优先级、界面、错误处理及安全边界见[AI 命令执行规则与危险操作确认](assistant-command-policy.md)。

本机命令权限的界面说明采用通用表述“允许在本机运行命令和程序”，不以设备访问、固件烧录或工具安装等举例限定能力。批准面板不再重复显示自定义权限的说明，只保留简短的本次风险原因及一条执行范围提醒，统一放在操作标题下方、完整命令上方，与正文一起滚动。说明合并为单一文本段落，各句用空格连接，不插入强制换行，宽度不足时自然折行；行高为 1.5，与聊天正文一致，不额外叠加说明行之间的块间距；操作目的、工作目录按标签和值分组显示，标签与正文间距 4 px，组间距 12 px。执行权限及命令风险检查逻辑不随文案精简而改变。
